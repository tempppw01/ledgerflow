## 修:导入的账单全部变成「餐饮」

### 根因

账单导入给**每一行**都用同一个 `defaultCategoryId`:

```ts
categoryId: input.defaultCategoryId,
```

而导入向导里那个默认分类通常是「餐饮」。于是 445 笔交易(停车、医院、超市、话费、转账……)
全部归到餐饮 —— 分类统计、预算执行数、分类排行全部失真,而界面上看不出任何异常。

### 改法:按每行内容推断分类

项目里**本来就有**分类推断器(助手导入账单时在用):按「交易对方 + 商品 + 备注 + 交易类型」
匹配关键词,返回分类名;再按名字解析成 id。这次把它接到账单导入上:

- 推得出来 → 用推断出的分类(停车→交通、医院→医疗、超市→购物、工资/转账→收入……);
- 推不出来、或用户的分类里没有这一项 → **退回原来的默认分类**(行为不倒退);
- 没传 `categories` 的调用方 → 保持旧行为(全部用默认值),不影响已有调用方与测试。

### 验证

新增 2 条测试(用一段真实的微信账单行):

| 行 | 期望分类 | 结果 |
| --- | --- | --- |
| 智慧停车 · 停车场 | 交通 | ✓ |
| 东莞市寮步医院 · 诊查费 | 医疗 | ✓ |
| 永辉超市 · 日用品 | 购物 | ✓ |
| 转账收入 | 收入 | ✓ |
| 某不知名小店 | 默认分类 | ✓ |

并断言**分类不止一种**(`distinct.size > 1`),这正是这个 bug 的形状。

**证伪**:把那一行改回 `input.defaultCategoryId` → 第一条立刻失败,报错是
`expected 'cat-food' to be 'cat-transport'` —— 字面对应「全部变成餐饮」。
