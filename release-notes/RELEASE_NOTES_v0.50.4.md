## 刚性与灵活:住房不再从「灵活预算」里分 ¥200

这一版 1 个提交。

### 症状

智能预算页上,「住房」显示:

- 预算 **¥206**
- 已花 **¥6,500**
- 执行率 **超支 >999%**

而演示账本的房租是**每月固定 ¥6,500**,用户也早就单独声明了「固定支出 ¥3,000」。

### 为什么

「固定支出 ¥3,000」是一笔**没有归属的总额**:它从可支配收入里被减掉,
但从不落到任何分类上。与此同时,灵活预算(¥4,900)却被按身份权重
摊到账本里**所有**非核心分类 —— 住房、保险、水电燃气、通讯网络、还款、
税费 全都在里面。

于是:

1. 住房从这个池子里分到 ¥206,和实际房租差了两个数量级
2. 这 ¥206 还是**从餐饮、交通这些真正的灵活费用里抢来的**
3. 界面老老实实按 6500 / 206 算执行率,报出一个读者无法使用的数字

上一版记录过「这是产品建模问题,需要决策,不擅自改」。这一版就把它定下来了。

### 怎么定的

**刚性支出 = 每月固定要付、金额基本不受当月取舍影响的分类**:
住房 / 房租 / 房贷 / 租金 / 物业、水电 / 燃气 / 取暖、还款 / 贷款 / 分期、
保险、税费 / 税务、通讯 / 话费 / 宽带 / 网费。

判断规则:**这类钱由用户自己声明的「固定支出」承担,不参与灵活预算分摊。**
不去猜每个刚性分类该分到多少 —— 那需要一年以上的账单数据才站得住脚,
而用户已经用一个数字表达过自己的意图了。

- `budgetPlan.ts` 新增 `isRigidExpenseCategory`
- 灵活预算只分给真正灵活的分类;分不到任何灵活分类时(全刚性,退化情形)
  退回按全部分类分摊,保证「分类合计 = 月收入」这条不变量不被破坏
- `BUDGET_DISTRIBUTION_VERSION` 2 → 3:已有方案在下次载入时自动重算一次
  (重算后仍保留之后的手动调整,不会每次都覆盖)
- 向导确认页补一句说明,**免得用户以为预算把房租漏掉了**

### 演示账本上的实际变化

| | 修复前 | 修复后 |
| --- | --- | --- |
| 灵活分类数 | 17(含 6 个刚性) | **11** |
| 住房 | 预算 ¥206 / 超支 >999% | 不再单列,归入「固定账单」 |
| 餐饮预算 | ¥448 | **¥539** |
| 已超支分类 | 6 | **0** |
| 灵活池合计 | ¥4,900 | ¥4,900(不变) |
| 分类合计 | ¥10,000 | ¥10,000(不变) |

在真实浏览器里确认:载入后方案自动重算为 v3、住房消失、`>999%` 消失、
「已超支 0」、健康度 100;向导确认页显示 13 行(固定支出 + 储蓄 + 11 个灵活分类)
并带那句说明;退出向导并刷新后数据不变。

### 验证

- 新增 3 条用例:刚性分类不参与分摊、刚性分类不再抢走灵活分类的额度
  (同一分类集合带不带刚性分类,餐饮拿到的钱必须一致)、全刚性时的退化回退。
  **逐条临时还原修复后确认会失败**
- 顺带修正一条旧用例:它把「保险」当灵活分类,断言的正是这次要改掉的行为
- 前端 **1073 项 / 141 文件**、服务端 **38 项**
- `tsc` 0、`eslint --max-warnings=0` 0、i18n 两闸门 0、`check:dates` 0、`check:money` 0
- `npm run audit:ui`:18 个路由 × 桌面/移动 = **36 个组合,0 个问题**

### 仍然没做的

- **刚性支出的分月对账**:现在「固定支出 ¥3,000」仍是一笔总额,
  预算页不显示「这个月固定支出实际花了多少 / 和声明差多少」。
  要做得可信,得先把刚性分类归并成一个可点击的合计行,
  这是下一步,不是这一版能顺手带上的
- 用户声明的 ¥3,000 远低于实际刚性支出(房租一项就 ¥6,500)。
  这是**用户输入**的问题,算法不该替他改数字 —— 但上面那条对账做出来之后,
  这个落差会第一次变得可见
