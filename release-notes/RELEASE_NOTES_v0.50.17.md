## 恢复一笔「已退款」的支出,退款单却留在回收站里 —— 账上凭空少一笔

这一版 1 个提交。

### 症状

演示账本里有一对:支出「家居小物 ¥390.55」及其退款单「退款:家居小物 ¥390.55」。
删掉那笔支出再恢复,余额**回不到原样**:

| 步骤 | 支付宝余额 |
| --- | --- |
| 删除前 | −26,556.20 |
| 删掉支出(两条一起进回收站) | −26,556.20(一收一付净额为 0) |
| **只恢复那笔支出** | **−26,946.75** ← 凭空少 ¥390.55 |

同时:活跃交易 297(基线 298),退款单还躺在回收站里;而那笔支出状态是「已退款」,
**退款记录却找不到**。

### 根因:删除与恢复不对称

```
removeTransaction   会把「退款/冲正」附属行一并移送回收站
                    (确认框也明确写了「其中 1 笔退款/冲正会一并移入回收站」)
restoreTransaction  只恢复指定那一行        ← 没有跟上
```

`removeTransaction` 当初加级联,正是为了避免「删掉 ¥100 支出、留下 ¥40 退款,余额反而多出 ¥40」
—— 恢复侧漏了同一件事的另一半。

### 改法

`restoreTransaction` 与 `removeTransaction` 共用同一套配对规则:把
「`refundOfTransactionId` 指向它 + 是退款/冲正 + 当前在回收站」的行**一起恢复**。

### 验证

- 新增 3 条回归测试(删除级联、恢复后**余额一分不差**、单独恢复退款单后还能补回来);
  把恢复退回「只恢复一行」,第二条即失败
  (`expected [ 'tx-1' ] to deeply equal [ 'tx-1', 'tx-1-refund' ]`)
- 浏览器实测完整走一遍:删掉支出 → 回收站 **2 项**;恢复「支出」那一条 → 回收站 **0 项**
  (两条一起回来);支付宝余额回到 **−26,556.20**、活跃交易 **298**、回收站 **0**,
  与基线逐项一致
- 前端 **1100 项 / 144 文件**、服务端 **38 项**
- `tsc` 0、`eslint --max-warnings=0` 0、i18n 两闸门 0、`check:dates` 0、`check:money` 0、
  `check:shared-predicates` 0、`audit:ledger-math` 通过
- `npm run audit:ui`:36 个组合,0 个问题

### 一个诚实的小插曲

验证时我自己的脚本用**半角**冒号去匹配备注,而库里是全角「退款:」,结果误点了退款那一条 ——
反而顺手验证了「只恢复退款单」这一支的行为,与我新写的测试一致(余额会多 ¥390.55,
把原交易恢复回来即回到基线)。所有临时改动已还原,演示账本回到基线。

### 仍然需要你拍板(第五次提出)

`isExpenseLike`(支出 + 预算 + 还款)与首页的 `isActualExpenseType`(支出 + 还款)对
**「预算」型交易**判断相反:记一笔 ¥100 的预算型交易后,页头「本月结余」减 100,
而「钱都去哪了」各分类合计不变。这是口径清单里唯一没收敛掉的一项。
