## 状态一致性:日期归属、跨实体引用、随机扫描

这一版修的两个问题都属于「同一份状态被不同地方按不同规则理解」,另外加了一个随机操作扫描
作为长期防护。

### 1. 列表显示与筛选按 UTC 取日 —— 凌晨记的账显示成昨天,还会掉出「本月」

交易的 `date` 有两种形态:纯日期和**带时间的 ISO 瞬间**(用户在编辑页选的是本地时间)。
而列表与筛选一律用 `date.slice(0, 10)` —— 按 UTC 取日:

```
用户选 2026-11-01 00:30 → 存 2026-10-31T16:30:00.000Z
列表显示/筛选 = 2026-10-31   本地日 = 2026-11-01   ← 不一致
```

后果两条,都出现在**月初那几小时**:

1. 列表把「今天凌晨记的账」显示成**昨天**
2. 它同时从「本月」筛选里掉出去(10-31 不满足 `>= 11-01`),月统计少一笔

新增 `resolveTransactionLocalDay()`(纯日期原样、带时间的取本地日),替换了 **10 处**
按 UTC 取日的用法:列表的区间筛选、快速筛选、图表按日聚合、列表显示、打印预览、导入去重身份串,
以及助手页的「今天」判定与重复账单核对弹层。

### 2. 订阅绑定的账户被删后照样写流水,留下悬空账户引用

`const accountId = subscription.accountId || s.accounts[0]?.id` —— 只看「填没填」,
不看「账户还在不在」。账户删掉后订阅仍留着旧 id,于是照样写出一笔流水:

- `computeAccountBalances` 匹配不到任何账户 → 这笔钱**不出现在余额里**
- 但它出现在交易列表与支出统计里 → **同一屏两套数**

现在会显式校验:绑定的账户已不存在 → 拒绝写入并提示「请先重新指定账户」。

### 3. 新增:随机操作序列的不变量扫描

12 种操作 × 300 步随机序列(固定种子、可复现),每一步之后检查:

1. **账户余额 = 初始余额 + Σ(影响余额的流水)**,且为有限数
2. **同一 id 不同时出现在「在用」与「回收站」**,数组内不重复
3. 所有金额字段都是有限数(无 NaN/Infinity)
4. 操作不抛「未预期的错误」(预期内的业务拒绝除外)

**结果:通过** —— store 核心状态机在 300 步混合操作后仍自洽。

两道防「空转」的保险:**覆盖率断言**(确认真的执行了各类操作)+ **反向验证 3 项**
(人为改错余额 / 造重复 id / 塞 NaN,检查器必须报出来)。一个恒真的检查器没有价值。
