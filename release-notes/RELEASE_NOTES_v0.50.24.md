## 助手说「本周比上周多了 X%」时,其实是按行号切的

这一版 1 个提交。

### 症状

助手页的消费洞察里有这样一句话术:

> 近 7 天餐饮/日常消费较上周**增加 X%**
> 本周支出 ¥X,上周 ¥Y

而它的算法是:

```
weeklyRows.filter(type === 'expense').slice(0, 7)    ← 当「本周」
weeklyRows.filter(type === 'expense').slice(7, 14)   ← 当「上周」
```

**按行号切,不是按日期切**。而 `weeklyRows` 来自 store 的**原始顺序**(并没有按日期排序),
所以「本周」实际是「列表里的前 7 笔」。

用真实形状的数据复现(上周 5 笔 ¥10、本周 2 笔 ¥100):

| | 本周 | 上周 |
| --- | --- | --- |
| 旧写法 | **¥250**(把上周两笔也吞进本周) | **¥0** |
| 正确 | **¥200** | **¥50** |

某周只有两三笔时,切分更没意义 —— 比如本周只记了 2 笔,那 7 行的窗口会一路吃到上周去。

### 改法

抽成 `src/features/assistant/model/weeklyExpenseTrend.ts`:按**本地日历日**分桶
(0–6 天 = 本周,7–13 天 = 上周),与列表、筛选、财务分析同一套日期口径;
退款抵减、排除不计入余额的状态都走共享的 `summarizeTransactions` /
`filterCountableTransactions`。上周为 0 时 `deltaPct` 返回 `null`(没有可比基线),
页面沿用原来的话术分支。
