## 订阅生成支出:补上四条不变量,并修一处会误导人的提示

### 发现

「订阅 → 生成支出」这个函数有四个不变量,**一条测试都没有**(`features/subscriptions/model` 里测的是品牌图标与状态,不是它):

1. 订阅绑定的账户被删了 → 拒绝生成(否则会留下指向不存在账户的流水:余额里看不到、支出统计里却有);
2. 同一天重复点 → `duplicated: true` 且**不新增**流水;
3. 生成成功 → 续费日/到期日**推进一期**,并记下**推进前**的值(删除流水时要精确退回 —— 日期推算有损:1月31日 +1月 = 2月28日,倒推回不到 1月31日);
4. 非人民币订阅 → 交易带「币种:XXX」标签与原币种备注。

### 修了什么

写测试时发现:**一个账户都没有**的时候,提示是「**订阅绑定的账户已不存在**」✗ —— 技术上没错(旧的 accountId 确实不存在了),但会误导:用户**根本没有账户**可指定。

改成先判断「一个账户都没有」→ 提示「当前没有可用账户,无法生成支出记录。」;只有"有账户、但绑定的那个被删了"才说「账户已不存在」。

### 测试:6 条

覆盖上述四条 + 「完全没有账户」+ 「订阅不存在」。其中「完全没有账户」这一条**在修复前就是失败的** —— 它本身就是这次修复的证据。
