## 修:两条"看着改了、其实一个字都没生效"的窄屏规则,以及键盘看不到的焦点

上一批修的是"该有的响应没有"(触摸端的悬停守卫、系统偏好)。这一批是同一层里更难看见的一类:
**声明写了,浏览器不执行,而且不报错** —— 以及一个键盘用户 Tab 过去什么都看不到的按钮。
两条都是"读代码觉得没问题、量了才发现"的,所以这一批的重点也在怎么让它们以后自动被抓出来。

### 一、窄屏「静默失效」两处:flex 父级里的 grid 属性

`grid-column: 1 / -1` 写在 `display: flex` 的父级里**完全不生效**(不报错、不警告,
连 computed style 都照样回显指定值)。全仓库扫一遍,53 条候选里查出 2 处:

| 位置 | 声明 | 后果 |
| --- | --- | --- |
| `今日财务看板` 的「净资产构成」 | `grid-column: 1 / -1` | **720px 三列各 48px**,标签与金额都被省略号截掉 |
| 欢迎横幅的指标块 | `justify-self: stretch` | **641~900px 一整行空掉一半**(768px 右侧空 445px) |

第二条尤其典型:`justify-self` 在 flex 父级里无效,**而且** `stretch` 本来就是 grid item
的默认值 —— 这条声明即使父级换成 grid 也只是废字。它想要的"撑满",
同一个文件下面 `@media (max-width: 640px)` 块里早就用 `width: 100%` 写对了,上面那段没跟上。

第一条还叠了一个隐藏问题:补 `flex: 0 0 100%` 后**仍然不换行**,因为 `global.css` 里
`.stat-card > div { flex: 1; min-width: 0 }`(0,1,1)也命中摘要、优先级高于
`.dashboard-net-worth-summary`(0,1,0)—— 连 base 里的 `min-width: 210px` 也是被它静默清成 0 的
(实测 `minWidth = 0px`)。

| 视口 | 看板三列 | 欢迎横幅指标块 |
| --- | --- | --- |
| 640px 及以下 | — | 改前改后一致(`width: 100%` 那条在管) |
| 720px | 48px → **105px**,0 截断 | — |
| 768px | — | 225px(右空 445px)→ **670px 铺满** |
| 900px | — | 225px(右空 286px)→ **511px 铺满** |
| 390 / 439px | 挤成 2+1 两行 → 摘要独占整行,三列 106 / 122px,卡片高度与邻卡齐平 | — |
| 1180 / 1440px | — | 完全一致(1180px 那处空白是**按钮列**的位置,量过确认不是漏排) |

### 二、≤768px 的「深色 / 浅色」是 0 宽焦点(2.4.7)

主题切换器在窄档折叠成"只露当前主题",点当前项才展开。底座那条折叠规则带了
`:not(:has(.theme-icon-btn:focus-visible))` 例外,而 `@media (max-width: 768px)` 那段**漏了**。
于是窄档下这两个按钮是 `width: 0; opacity: 0; pointer-events: none`,**却仍在 Tab 序列里**:

```
Tab#5 焦点 44x44 「跟随系统」  按钮宽度 [44x44* 0x32 0x32]
Tab#6 焦点 0x32 「深色」       按钮宽度 [44x44 0x32* 0x32]
Tab#7 焦点 0x32 「浅色」       按钮宽度 [44x44 0x32 0x32*]
```

按 Enter 还会真的换主题 —— 键盘用户看不到自己选中了什么。窄窗口的笔记本、
外接键盘的手机、开关控制用户都会踩到。

**2.5.8 的尺寸检查抓不到它**:那条看到 0 宽元素会当成"不可见"跳过,而缺陷恰恰是
"不可见却可聚焦"。补上同一个例外后复测:初始 44x44 / 点当前项 136x44(展开)/
点另一个主题后收回 44x44 且主题真的换了 / Tab 进切换器 136x44 / Tab 离开收回 44x44 ——
鼠标与触摸用户看到的仍是折叠态,只有键盘聚焦才展开。

### 三、两个新致败项:让这两类问题以后自己冒出来

| 检查 | 判据 |
| --- | --- |
| `inertGridRules` | 窄屏 `@media` 里声明了 grid 专属属性,而命中元素的**父级** computed `display` 是 flex/inline-flex |
| `focusWalk` | 每条路由按 Tab 走 60 步:焦点元素宽或高 < 2px / `opacity: 0` / `visibility: hidden` / 完全在视口外(2.4.7);或四角+中心 5 个采样点**全部**被 sticky/fixed 内容盖住(2.4.11,AA 只要求"不完全被遮住") |

两处都刻意避开了各自的假阳性来源:

- `inertGridRules` 必须先判「规则在当前视口 `matchMedia().matches`」,否则会把
  「这个宽度轮不到这条规则」误报成「规则无效」—— 我的探针第一版就这么在 1024px 档误报了 6 条;
- `focusWalk` 在"可疑"之后要**等 320ms 再量一次**才判定:折叠展开是 `width` / `transform`
  过渡,一按 Tab 就量会抓到中间帧(实测 `1x22`、`opacity: 0`),那不是稳定状态。

`focusWalk` 第一版只在桌面档跑,结果它**抓不到**自己刚修的那个 bug(例外写在
`@media (max-width: 768px)` 里),已改成三档都跑(实测约 130~190ms/路由)。
「触屏没有 Tab 键」这个理由也不成立:窄视口不等于触屏,外接键盘、开关控制、
读屏器虚拟光标都会产生真实焦点。

### 四、WCAG 2.5.3(Label in Name,AA):18 → 3,并且更正了我自己报错的数字

可见文字必须出现在无障碍名称里。真实违规 15 处已修,剩下 3 处是
「可见文字是**值**、不是标签」(`lf-date-trigger` 显示 `2026-11-27`,名称是「选择日期」),
2.5.3 管的是标签,不在适用范围 —— **没有为了清零去改它们**。

这一节要单独说一句:`ccecc42` 那次提交里我报的"27 → 5"是**错的**。
我把无障碍名称的优先级记反了(`aria-label > title > 内容`,实际是
`aria-labelledby > aria-label > 内容 > title`,`title` **不会**盖掉按钮的文字内容),
于是把 9 处本来没问题的元素也改了一遍。用 CDP 的无障碍树对齐后确认它们是**内容**胜出,
那 9 处改动已撤,数字更正为 18 → 3。`1b10a0d` 记了这件事的来龙去脉。

### 顺带确认**不是**问题的三件

- **"后退不先关抽屉"**:实测抽屉是 `[aria-modal]` + Escape 关闭,关闭后焦点回到
  触发它的那一行,再按后退才回 `/`,没有留下失效的模态 —— 不是 bug,查清写进文档,免得被"修坏"。
- **1180px 档右侧 200 多像素的空白**:那是按钮列的位置,不是漏排。
- **2.5.8 剩下的那几项**:同样是"值不是标签"与行内豁免,不是漏改。
