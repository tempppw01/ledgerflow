## 口语输入的正确性

用户最自然的说法往往不是标准格式:「欠款 1.5 万」「分12期已还3期」「1万零500」。
这一版把这类表达的解析补齐 —— 4 个修复的共同点是**读错时用户看不出来**,
只是账目数字不对。

### 1. 「万 / 千」单位完全没解析(差 10000 倍)

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `花呗欠款 1.5 万` | **¥1.5** | ¥15000 |
| `信用卡总欠款 2万` | **¥2** | ¥20000 |
| `白条欠款 3 千` | **¥3** | ¥3000 |

债务金额动辄上万,「万」也是最自然的说法;而用户在确认页看到「待还 ¥1.50」,
很难联想到是单位没解析。AI 通道同理(`positiveNumber('1.5万')` 会得到 1.5)。

### 2. 万位后的低位被丢掉

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `欠款1万零500` | **¥10000**(少 500) | ¥10500 |
| `欠款1万500` | **¥10000** | ¥10500 |

现在「万」后面按三种口语写法分别处理:`零 N` 加低位、多位数字加低位、单个数字按千位。

### 3. 「分12期,已还3期」被读成「还剩12期」

期数其实是**三件事**(总期数 / 已还 / 剩余),旧实现把裸「N期」一律当剩余,且**完全没解析已还期数**:

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `花呗分12期,已还3期` | 剩余 **12** | 总 12 / 已还 3 / 剩余 **9** |
| `还剩6期没还` | 剩余 6,**还被当成总期数 6** | 剩余 6,总期数不误填 |
| `已还3期` | 剩余 **3**(错的) | 已还 3,不猜剩余 |

影响:剩余期数偏大会让还款计划与**剩余利息整体高估**(12 期 vs 实际 9 期,利息多算约 33%)。

### 4. AI 记账结果的三处健壮性问题

模型输出的形状不可控,用「形错」样本实测出:

- **单号是数字会丢掉整张识别结果**:`row.orderNo?.trim()` 对 `12345` 抛 TypeError,
  而调用处把它当成「模型返回的是分析文本」→ 整张单子静默消失
- **猜出来的日期没有标记待核对**:模型没给日期时退回「今天」,但不进 `needsReview`
- **备注里出现 `}` 会截断 JSON**:括号配对没跳过字符串,导致解析失败 → 同样丢整张单子

### 顺带:利率口径已核实一致

`annualRate` 存的是**百分数**(18.25 = 18.25%),三处消费方(还款页月供、还款页利息、
资产负债模拟)都除以 100。已用测试钉住,并显式断言「误当小数会差 100 倍」。

### 故意不做的

**纯中文数字不解析**(「欠款五千」「三千五」)→ 金额字段留空,由「待补字段」提示用户填写。
安全失败比猜错强,已写进 `docs/verified-invariants.md`。
