## 同一个页面,名字在三个地方不再各说各话;死代码闸门补上两个洞

这一版还是「同一件事被两处分别计算」那条线,外加把一道闸门的洞补上。
另外记了三件**查证后没有改**的事(避免以后重复怀疑)。

### 一、顶栏 h1 与浏览器标签同源:子路由不再显示所属工作区的名字

一个页面的名字出现在三个地方:侧栏导航项、顶栏那个唯一的 `h1`(它同时是 `<main>` 的
`aria-labelledby` 目标)、以及浏览器标签/历史/读屏器先读到的 `document.title`。它们原来由
**两套逻辑**分别算:标签走路由表,顶栏按**侧栏导航前缀**自己猜。顶层 18 条路由恰好一致
(所以看截图看不出问题),一进子路由就漂:

| 路由                | 浏览器标签 | 修改前的顶栏           |
| ------------------- | ---------- | ---------------------- |
| `/transactions/new` | 记一笔     | 交易流水               |
| `/transactions/:id` | 编辑流水   | 交易流水               |
| `/settings`         | 设置       | 账号设置(三个页签之一) |

现在两边走同一张表(`resolvePageTitle`),`文档标题 = 页面名 · 应用名` 由单测钉住,
所以不可能再漂开。

### 二、助手工作区:标签标题跟着工作区走(按标签页存的,更要跟)

助手工作区的名字跟着当前工作区变(AI 助手 / AI 信贷管家 / AI 投资助手),而**模式存在
sessionStorage 里、按标签页各存一份** —— 侧栏与顶栏都按工作区取名,标签却一直读路由表里的
「AI 助手」:

| 工作区模式   | 侧栏项      | 顶栏 h1     | 标签标题(修改前) |
| ------------ | ----------- | ----------- | ---------------- |
| `assistant`  | AI 助手     | AI 助手     | AI 助手 ✓        |
| `credit`     | AI 信贷管家 | AI 信贷管家 | **AI 助手** ✗    |
| `investment` | AI 投资助手 | AI 投资助手 | **AI 助手** ✗    |

两个标签页真的可以停在不同工作区,标题一样就分不清谁是谁 —— 而这正是 WCAG 2.4.2
(Page Titled)要避免的。现在 `useDocumentTitle(pathname, pageTitleOverride?)` 允许把页面名
直接传进来,顶栏那句动态名字同时喂给两处。

### 三、死代码闸门:补两个洞,顺手清掉两处冗余导出

`check:dead-exports` 有两个洞,补上后**立刻抓到三个真东西**:

| 洞                                                     | 后果                                                                                                  | 抓到的                                                                                                            |
| ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| 测试文件也算「引用来源」                               | 「写好了、只有自己的测试在用、产品代码里没有入口」这一类完全看不见 —— 它的测试永远绿,因为测的就是自己 | `AccountPresetPicker`(没有任何页面渲染它)、`connectionClient` 的「测试连接」请求函数(全仓没有那个按钮)            |
| 闸门自己就在 `scripts/` 里,注释与 `ALLOW` 清单也算引用 | **在闸门注释里提一句符号名 = 给自己发豁免**                                                           | 在闸门注释里写下 `isCacheValid` / `BUDGET_ACTION_LABEL` 之后,这两个没人调用的导出立刻从红变绿(而它们一直躺在原地) |

改法:引用只数**非测试代码**,并排除闸门自身;`.d.ts` 跳过(声明的是全局类型)。
两处「写好了没接线」以带理由的 `ALLOW` 挂账,等决定(接上还是删掉)。

另有两处**人工核查**发现的冗余导出已删(新判据按设计仍不覆盖「活得好的文件里个别导出没人用」,
历史上按符号逐个判定时 33 个里 25 个误报):`isCacheValid`(只有一行,而 `readCache` 自己
已经判过 6 小时 TTL)、`BUDGET_ACTION_LABEL`(调用点把文案写在 `BudgetActionLog.message` 里)
—— 后者还顺带删掉了 `.ts` 里唯一一处不会被 `i18n:check-jsx` 看到的硬编码中文。

**破坏性验证**

| 破坏方式                              | 期望                                 | 实测                                                     |
| ------------------------------------- | ------------------------------------ | -------------------------------------------------------- |
| 去掉「闸门自身不算引用」的过滤        | 两个没人调用的导出重新隐身、闸门变绿 | exit 1 → **exit 0**;恢复后逐字节一致                     |
| 去掉 `AccountPresetPicker` 的 `ALLOW` | 它必须被报出来                       | exit 1,`✗ AccountPresetPicker.tsx → AccountPresetPicker` |
| 顶栏改回按侧栏前缀猜                  | 单测与真机探针双双变红               | 单测 17 里红 2;真机 3 条命中(正是表格那三行)             |
| 去掉助手的标签覆盖                    | 同上                                 | 单测红 1;真机三模式里 2 条命中                           |

### 四、这一版查证过、**没有改**的事

- **`/tags` 与 `/investments/flow` 的「标题重复」不是问题**:两者都是
  `<Navigate replace>` 重定向别名(`/tags` → 账户与分类,`/investments/flow` → 投资理财),
  路由表里按各自目标取名是对的。
- **每个页面都能从界面走到**:21 个页面里 18 个在侧栏、`/settings` 在账户菜单、
  记一笔与编辑流水由页内按钮进入 —— 没有只能靠手敲 URL 的页面。
- **点击目标尺寸符合 WCAG 2.5.8(AA,24×24)**:审计里那项 `targetSize25x8` 本来就带
  行内、用户代理、间距三条豁免,69 个组合 **0 命中**;另用独立探针在 390px 宽下单独量过
  `/about`:13 个矮链接(20~22px)最近的目标中心距都 > 145px,间距豁免成立。审计里那 42 组
  `smallTargets` 是 44px(AAA / iOS)那档,只报告、不致败。
