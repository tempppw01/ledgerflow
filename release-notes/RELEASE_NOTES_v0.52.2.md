## 首屏少下 2.3 MB;投资页不再把同一轮行情打六遍

这一版没有新功能,全是「已经画在屏幕上、却在偷偷浪费或说错话」的东西。三条主线:
品牌图不再为一个 32px 的图标去拉 2.3 MB 的原图、两个没人引用的资源不再被打进包里、
投资页的行情兜底不再重复打上游(顺带修掉一个会把已有行情覆盖成「--」的真 bug)。
另有两处上一批的收尾:侧栏图标失败退回字形、侧栏第一组的组名不再和项目重名。

### 一、品牌图:同一个原图,按用途生成五张小图

侧栏 logo 只画 32px、favicon 只需要 48px,但它们指向的都是 R2 上那张 **1254×1254、
2,318,110 B** 的 PNG —— 打开页面先下 2.3 MB 位图,弱网下还会先出现一个空方块。
`index.html` 里两个 `<link>` 甚至都声明着 `sizes="1254x1254"`。

现在从同一张原图生成五档按需尺寸(Pillow LANCZOS + MEDIANCUT 量化),放进 `public/`
由 nginx 同源发出;原图继续留在 R2,需要大图时仍可从那儿取。

| 文件                          | 尺寸    | 字节                        |
| ----------------------------- | ------- | --------------------------- |
| `public/favicon-48.png`       | 48×48   | 1,492                       |
| `public/logo-128.png`         | 128×128 | 8,671                       |
| `public/apple-touch-icon.png` | 180×180 | 19,402                      |
| `public/pwa-192.png`          | 192×192 | 21,605                      |
| `public/pwa-512.png`          | 512×512 | 129,501                     |
| 合计                          |         | **180,671**(替代 2,318,110) |

真机实测(Playwright 全新上下文、登录后重新进入首页):

| 量的是什么           | 改前                         | 改后                                       |
| -------------------- | ---------------------------- | ------------------------------------------ |
| 品牌相关请求         | 2,318,110 B(R2 原图)         | 1,492 B + 8,671 B(同源小图)                |
| 「打开首页」传输合计 | 4,435,720 B                  | **2,118,187 B**(−52%)                      |
| 侧栏 logo            | natural 1254×1254 / CSS 32px | natural 128×128 / CSS 32px,complete 且可见 |

生产构建里也逐条核对过:`index.html` 声明的 `sizes` 与 PNG 真实像素一致(48/180),
PWA manifest 的 192/512 一致,打包后的 JS 不再出现旧的 `logo.png`。

### 二、两个没人引用的资源:223 KB 白进包、白进 Service Worker 预缓存

`public/logo.png`(223,137 B)与 `public/icon.svg`(603 B)在源码、`index.html`、
`vite.config.ts`、docs、scripts、workflow 里都已无引用 —— 但 vite 会原样拷进 `dist/`,
workbox 的 `globPatterns` 又会把它们列进预缓存清单,于是**每个老用户下次装新版 SW
都会再拉一次这张 223 KB 的死图**。删除后:dist 少 223,740 B,预缓存清单里换成五张
新图(合计 180,671 B,比原来那一张还小约 43 KB)。

### 三、投资页行情:兜底不再重复打上游,并且不再把已有行情覆盖成「--」

取 5 个主要指数行情时,先批量查一次,批量整批失败再退化成 5 次单指数请求兜底 ——
这条兜底本身有用(救「批量被拒、单个还能用」的部分故障),但它有两个代价:

1. **重复**:页面挂载时 `StrictMode` 会把 effect 跑两遍,应用内跳走再回来也会再要一次,
   每次调用都重放一整轮(1 次批量 + 5 次兜底)。
2. **会把已经取回来的行情覆盖成「--」**:两次调用都在途时,后发的那次落到
   「兜底被跳过 / 缓存还没热」的分支返回空数组,而它的 setState 后落地。

改法:**在途共享**(同一时刻只打一轮,后来的调用等前一轮结果)+ **兜底冷却**
(只有「批量本身抛错」才计入 60 秒冷却;批量成功但少几条属于数据缺口,每次都照补)。

真机实测(拦截批量请求为 500、单只放真行情;用 `vite preview` 起**生产构建产物**,
避免开发环境双挂载干扰):

| 场景                     | 改前                | 改后                    | 界面上的 5 个指数值      |
| ------------------------ | ------------------- | ----------------------- | ------------------------ |
| 首次进 `/investments`    | 1 批量 + 5 兜底 = 6 | 6(第一次兜底必须留)     | 完整显示                 |
| 应用内再进一次(冷却期内) | 1 批量 + 5 兜底 = 6 | **1 批量 + 0 兜底 = 1** | 完整显示(用缓存)         |
| 两次合计                 | 12                  | **7**                   | 完整显示                 |
| 开发环境同一序列         | 24                  | 7                       | 完整显示(改前会变「--」) |

交易时段每 10 秒一轮的轮询走的是同一条「冷却期内再次调用」路径,所以上游整体故障时
每轮只剩 1 次批量请求(原来每轮 6 次),而部分故障仍保有第一次兜底机会。

### 五、审计工具自己修的两个坑

- **失败请求单独记一份**(状态码 + 方法 + 路径,重复合并成 ×N),报告顶层还有全路由去重的
  汇总。原来只有一句 `Failed to load resource: 500`,不带 URL,定位不到是哪个接口 ——
  加完第一次跑就抓到原来找不到的 `500 GET /cdn/ui/calendar.svg` 等 4 个图标。
  判定口径没变;`requestfailed`(`net::ERR_ABORTED`,切路由时浏览器主动取消)只记录不算问题。
- **每条路由先等应用外壳渲染出来再量**:之前只等网络静默,于是会量到一张空壳
  (桌面档 `/` 被报成「没有主区域」)。确定性验证:人为把外壳渲染推迟 4 秒,
  去掉等待时 **23/23 条路由全部误报**,保留等待时 **0 条**。

### 七、审计里那 6 个 500 与本版无关

69 个组合里仍只有那 6 个问题,全部落在 `/investments` 与 `/investments/flow` × 三档视口,
且每条都指名道姓是 `500 GET /api/market/eastmoney/quotes?secids=...` 与 `/trend` ——
本机连不上上游 `push2.eastmoney.com`(直连 exit 000,本地 API 返回 `{"ok":false}`),
与页面代码无关。本版把**单次访问的失败请求从 14 条降到 7 条**,同时那 5 个指数值
照旧完整显示。
