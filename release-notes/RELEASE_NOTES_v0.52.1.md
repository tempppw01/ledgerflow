## 投资页两处「说的和做的不一致」:简报的结论、快讯的 AI 解读

这一版修的都是同一类问题:**界面上的一个元素,干的事和它看起来干的事不一样**。
「今天的市场,说人话」按涨跌幅阈值吐固定句子,数字与结论可以互相打脸;
7×24 快讯顶上那个「AI 解读」按钮,无论列表里是哪一条,问的都是第一条。

### 一、「今天的市场,说人话」:结论必须由当前数据推出来

原来顶上那句话是一组**与数据无关的固定句子**(按涨跌幅阈值吐「大盘又被砸了,先稳节奏」),
「领跌」那条也无条件读作"偏弱"。演示数据里最弱板块是 **+4.78%(所有板块都在涨)**,
面板照样写着「油气资源 +4.78%,今天偏弱,别急着接」—— 同一个元素里数字与结论相反。
根因是判定、取数、文案散在页面里,读代码看不出来。

现在读数与文案分开:读数在 `src/features/investments/model/plainBriefing.ts`(纯函数),
句子由组件按语言组装。规矩三条:数据缺了如实说缺什么、正负号不许自相矛盾、
结论要么由指数要么由板块支撑。

| 量的是什么                 | 重构前                              | 重构后              |
| -------------------------- | ----------------------------------- | ------------------- |
| 面板**内容**高度(1440)     | 355.3px                             | **173.1px**         |
| 面板内容高度(390 / 320)    | 265.9px                             | **186.1px / 227px** |
| 今日看板网格右侧空列(1440) | **282.2px**                         | **0px**             |
| 「领跌」那条               | `油气资源 +4.78%,今天偏弱,别急着接` | `没有下跌的板块`    |
| 资讯那一条                 | 铺整段新闻正文(实测一段 250 字)     | 只留标题,最多两行   |

### 二、7×24 快讯:问的必须是点下去的那一条

面板顶上原来**只有**一个「AI 解读」按钮,提示词里写死了 `news[0]` —— 列表里想看第 5 条、
切到「上市公司」分类,发出去的还是第一条的标题与摘要;而列表本身没有任何解读入口
(整行是一个 `<a>`,点哪儿都是跳东方财富)。变量名叫 `news`、实际只用了第一个元素,
读代码看不出来。

- **每一条快讯自己有一个「AI 解读」按钮**,绑定这一条的标题/摘要/关联标的。
  按钮不能放进 `<a>` 里(交互元素不能嵌套),所以行结构从"一个链接"改成
  `<article>` = 元信息行(时间 + 按钮) + 正文链接:点按钮不跳走,点正文照旧跳原文。
- **顶部按钮改成"批量挑重点"**:一次最多 5 条、摘要裁到 60 字(不然一条 250 字的正文
  会把"哪几条重要"淹掉),并要求 **"如果都不重要就直接说都不重要"** ——
  没有这句,模型会给每条都硬凑一个影响。

真机实测(`.audit/verify-news-ai.mjs`,1440 与 390):8 条快讯 **8 个**解读入口;
点第 3 条之后悬浮助手的聚焦标签变成 `正在看:中东部晴朗干燥格局持续,本月底至下月初迎大回暖`
(第三条,不是第一条);按钮尺寸桌面 24px / 移动 44px、与时间药丸重叠 0px;
按钮没有被塞进 `<a>`,正文链接仍是 `target="_blank"` 的原文。

### 三、两处修复都配了会变红的闸门

| 闸门                                                          | 保护的行为                                                                                                                |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| `plainBriefing.test.ts` / `PlainMarketBriefingPanel.test.tsx` | 全涨时**不给**"最弱"、不出现「偏弱」;样本为 0 时是 `unknown` 而不是"中性";指数与板块背离时说出来                          |
| `InvestmentsPage.newsAi.test.tsx`                             | 有几条快讯就有几个解读入口;点第 3 条时发给 AI 的是第 3 条的标题与关联标的、**且不含**第 1 条的;聚焦标签跟着被点的那一条走 |
| `investmentAi.test.ts`                                        | 提示词本身:9 条只进 5 条、摘要裁到 60 字、空标题不占位、全空返回空串                                                      |

新闸门都**证伪过**(把 bug 放回去必须变红):单条入口重新读 `news[0]` → 红 1;
顶部批量改成 `news.slice(0, 1)` → 红 2;删掉"都不重要"那句 → 红 1;裁剪上限改回 4000 → 红 1。
改完再 `git stash` 还原比对,确认恢复后是原文件。

### 四、审计里那 6 个 500 与本版无关(查证过程写在下面)

`npm run audit:ui`(69 个组合)这一版报 6 个问题,**全部是 `/investments` 三个视口下的
`consoleErrors: Failed to load resource: 500`**,其它项全为空。逐条查证:

- 浏览器里失败的请求只有 `500 /api/market/eastmoney/quotes ×10` 与 `/trend ×2`;
- `curl` 直打本地 API 得到 `{"ok":false,"message":"fetch failed"}`,再直连
  `push2.eastmoney.com` 连不上(exit 000)—— 全程没有前端代码参与;
- 把改动 `git stash` 到上一个提交再跑同一个探针,同样的 500 原样复现
  (`quotes ×12`、`trend ×2`)。

同期 `/api/market/eastmoney/fast-news` 返回 200,所以快讯面板自身的验证不受影响。
