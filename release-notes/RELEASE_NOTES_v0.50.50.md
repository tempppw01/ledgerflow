## 补上「再记一笔」的测试 —— 这条我当初明说没有单测

v0.50.41 上线「再记一笔」时,我在发布说明里写了一句实话:**只有浏览器+数据库验证,没有单测**。
这轮把它补上,做法不是硬测页面,而是把**与界面无关的逻辑抽出来**:

新增 `features/transactions/model/quickAddForm.ts`:

| 函数 | 管什么 |
| --- | --- |
| `validateQuickAddDraft` | 三个校验:没选分类 / 没选账户 / 金额不合法,顺序与原实现一致 |
| `applyKeepOpen` | 「再记一笔」之后表单该长什么样 —— **这个按钮唯一的承诺** |
| `buildQuickAddTransaction` | 草稿 → 交易(金额四舍五入、备注空则用默认文案) |

页面**真的改用了这三个函数**(不是只抽不用),原内联逻辑已删除。

### 测试:9 条

- 校验:通过 / 缺分类 / 缺账户 / 金额为 `0`、`-1`、`abc`、空 / **错误顺序**(先分类后账户)
- 再记一笔:**保留** 类型、分类、账户、日期;**清空** 金额、备注;且**不修改传入的草稿**
- 建交易:12.345 → 12.35;备注两端空白会被去掉;空备注用默认文案

### 抽出来时踩到一个真的坑(值得记)

第一版把 i18n 键**一起搬进了 model 层**,结果 `i18nChecker` 的自测立刻失败 ——
静态检查器只认**页面里**的 key 字面量,键搬走之后它以为那三个键**没人用**了,
下一步就可能把它们当死键删掉,而界面上明明在用。

修法不是改测试,而是**改分层**:model 只返回**原因码**(`selectCategory` / `selectAccount` /
`invalidAmount`),文案键留在页面层。写成 `{ key: '…' }` 而不是裸字符串映射 ——
这是检查器认得的形状。**逻辑层不该拥有 UI 文案**,这次是检查器替我把这句话钉住了。
