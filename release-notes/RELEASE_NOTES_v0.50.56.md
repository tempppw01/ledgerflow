## 修:一批"看着没事、实际坏了"的样式问题

这一轮的主题不是加功能,而是**把界面到底有没有按设计渲染出来这件事量一遍**。
一共 39 个提交,没有一个是靠"读代码觉得不对"改的 —— 每一条都有截图、计算样式或
浏览器实测数据支撑。有三条属于**用户能直接踩到**的问题,先说这三条。

### 最要紧的三条

| 问题                                         | 后果                                                                                          |
| -------------------------------------------- | --------------------------------------------------------------------------------------------- |
| 移动端某些输入框字号只有 11~14px             | iOS Safari **一聚焦就自动放大整页,而且不弹回来**,填个表单页面就花了(全站 5 条路由、19 个控件) |
| 余额变动页移动端表格的文字**骑在隔壁格子上** | 日期被标签底色盖住、标签压在说明文字上,两组字叠成一团读不出来                                 |
| 语义色被当成文字色用                         | 浅色主题下有 **25 条路由**存在对比度不达标的文字;深色主题此前**从来没量过**                   |

### 一、对比度:25 条路由不达标 → 0

WCAG 1.4.3 要求正文 4.5:1。原先把"成功/警告/危险"这些**语义色**直接当文字色用,
而它们是为色块设计的,当文字用普遍偏亮。做法不是逐个改颜色值,而是补一套配套的
`*-text` 文字专用色(`--color-success-text` 等),再按主题分别取值 —— 深色主题下的
对比度是这轮**第一次**被纳入测量。

实测覆盖 25 条路由 × 浅色/深色两套主题、5940 个文字节点,3444 个装饰性文字跳过。
顺手修掉一处真实的"读不到":320px 下市场柱状图的 6 个金额互相压字(WCAG 1.4.10)。

深色主题这里有个**不容易发现的坑**:`[data-theme='dark']` 和 `[data-accent-theme='x']`
特异性完全相同(都是 0-1-0),而强调色那段写在文件后面 —— 于是深色模式下强调色块
**赢过**深色块,把浅色主题的值钉在深色背景上。实测 `--color-primary-text` 在深色下
解析成 `#8a4a00`,对比度 2.68:1。修法是给深色+强调色的组合另写 `[data-theme='dark'][data-accent-theme='x']`
(0-2-0),五套主题逐条验证过。

### 二、有一批边框和底色**从来就没渲染出来过**

全仓库扫描"被 `var()` 引用却没有任何定义处"的自定义属性,原来有 **29 个 / 319 处引用**,
现在降到 **4 个 / 22 处**。其中有一类后果比想象中严重,专门做了对照实测:

| 写法                                                               | 未定义时的实际计算值 | 后果                          |
| ------------------------------------------------------------------ | -------------------- | ----------------------------- |
| `border: 1px solid var(--未定义)`                                  | `0px` / `none`       | **整条声明作废,边框直接消失** |
| `border-width:1px; border-style:solid; border-color:var(--未定义)` | `1px`                | 只丢颜色那条,边框还在         |
| `border: 1px solid var(--未定义, #00ff00)`                         | `1px`                | 有兜底值就正常                |

所以有些卡片"没有边框"不是设计如此,而是那条声明根本没生效。留下的 4 个都是
渐变第二个色标或品牌取舍,已在文档里逐个写明理由 —— **剩下的不是没修,是不该修**。

### 三、移动端:触屏相关的规则此前**一条都没被跑到过**

这是审计本身的问题,比单个 bug 更值得说:审计脚本给窄屏建浏览器上下文时没开触摸模拟,
Chromium 因此一直报 `pointer: fine`,全站 `@media (pointer: coarse)` 里那一批
"为触屏放大点按区域、抬高字号"的规则**从来没有被这个审计触发过** ——
它一直是在拿一个"窄桌面窗口"冒充手机。现在窄屏两档都带触摸模拟了。

补上之后立刻发现了上面那条 iOS 缩放问题。修法和验证:

- 那条防 iOS 放大的规则其实早就有,但它用的是裸元素选择器(特异性 0-0-1),
  **赢不了任何组件类**(0-1-0),全站 19 个控件被自己的类压到 11~14px,规则对它一直是失效的。
  现在改成 `pointer: coarse` 判据 + `!important`(并保留原来那档窄窗口规则不动)。
- 判据用 `pointer: coarse` 而不是只看窗口宽度:决定会不会放大的是**触屏**,
  iPad 横屏 1024px 一样中招,而窄桌面窗口不会。
- 实测修之前**没有任何控件大于 16px**,所以这条规则只会把过小的抬上来,不会把大字压小;
  修之后 43 个控件全部 16px。320/390 两档 × 粗细指针 × 21 条路由,横向溢出 0 不变。

余额变动页那张表则是三个问题叠在一起:`table-layout: fixed` 把列宽定死在百分比上、
窄屏用 `display: none` 隐藏两列 —— 但**隐藏只让格子不画出来,列本身还在**,
那两列的 14% + 17% 仍然占着 101px,把可见四列挤进 227px;被挤窄的格子又是
`overflow: visible`,内容就直接画到隔壁格子上了。清掉列宽、三列重新分配之后,
又发现日期被截成「11月1…」—— 因为日期和星期拼在同一个字符串里,截断只能从末尾吃,
先吃星期、再吃「日」、最后连「15」都吃掉。把两者在数据层分开、窄屏整块隐藏星期之后,
320px 上「11月15日」和「−¥320.00」都完整。

金额列的宽度不是估的:用同一套 12px 等宽数字实测
「−¥320.00」64px /「−¥198,819.40」92px /「−¥1,234,567.89」103px(+20px 内边距),
再按这个数反推百分比。

### 四、图标:emoji → 线性 SVG,并改走同源

账户卡片的回退图标原来是 emoji(💵 📱 🏦),同一个"信用卡"类型在不同地方写成不同的 emoji,
而且渲染尺寸和基线随系统字体变。现在改成 9 个线性 SVG,由**账户类型推导**而不是手写字段,
渲染尺寸和颜色都跟着 token 走。

图标地址也从 R2 公网域名改成同源 `/cdn` 代理。实测单张图标加载
**2833ms → 461ms**(curl 3.8~6.1 秒 → 0.45~1.05 秒),首屏 28 张图 0 张失败、0 次直连 R2。

### 五、审计本身也补了三项检查

缺陷修完就完了的话,下次还会犯。所以这三类问题都进了审计脚本(69 个组合:
23 条路由 × 桌面/390/320 三档):

| 新增检查                   | 是否致败 | 说明                                              |
| -------------------------- | -------- | ------------------------------------------------- |
| 触屏下表单控件字号 < 16px  | 致败     | iOS 会放大整页,真实可感                           |
| 格子里的内容画到隔壁格子上 | 致败     | 排除绝对定位浮层与中间有裁剪层的元素              |
| placeholder 显示不全       | 只报告   | 不违反任何 WCAG 条款,但"看不到的那半句等于不存在" |

三项都做了**破坏性验证**(把修复撤回,检查必须变红):撤掉字号修复 → 立刻报 12 处;
撤掉表格修复 → 立刻报 8 处。改回来都是 0。

另外顺带把两处过长的占位提示改短了:AI 助手输入框那句要 345px 而框只有 298px,
末句被裁在字中间。例子在框下面本来就有三个可点的 chip,占位提示不必再重复一遍。
英文界面那一行按钮更宽、输入框只剩 98px,所以英文要比中文更短 —— 这也是量出来的。

### 验证

- 前端 **178 文件 / 1322 测试**全过;服务端 65/65;`tsc` / `eslint` / 13 个静态闸门全绿。
- 浏览器审计 **69 个组合 0 问题**;对比度审计 25 条路由 × 两套主题 **0 处不达标**。
- 关键修复全部做了破坏性验证,并保留回归闸门。
- 桌面 1440px 的表格几何与改前**逐像素一致** —— 移动端的改动没有碰桌面布局。

### 需要你知道的取舍

- 有 4 个"未定义 token"**故意留着**:都是渐变的第二个色标,补个值反而会改变品牌观感。
  理由写在 `docs/a11y-contrast-audit.md`。
- `--color-text-placeholder`(#b0b5bc,2.06:1)**没有抬高**:WCAG 1.4.3 明确不把
  占位提示算作正文;抬上去会让所有输入框的提示读起来像已填的内容。改成修掉一处
  被误用在该 token 上的标题文字。
- 余额变动页窄屏**去掉了「类型」列**:320px 上四个字段挤不下,而金额不能截断、
  说明最该看清。类型在展开行里本来就有(点右侧箭头),属于按重要性做减法。
- 表格在 320px 属于 WCAG 1.4.10 明确豁免的"需要二维布局"内容,目标是
  **不压字、不裁字、不横向溢出**,而不是把所有字段都塞下。
