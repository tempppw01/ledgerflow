## 「简单录入」的负债刷新后内容全丢:三个字段从来没进过库

这一版 1 个提交。

### 症状

用「简单录入」建一笔负债 —— 只需填**还款项目 + 还款日期 + 本期应还金额** ——
刷新之后只剩一个名字:到期日、金额、连「这是简单模式」都没了,
界面上显示成余额 ¥0.00、**「待补日期」**的普通负债。

用户丢的是**还款提醒本身** —— 那正是这个功能存在的唯一理由。
演示数据里已经有受害者:「11 月房租缴费」在库里 `balance=0`、计划字段全空。

### 怎么找到的

不再靠逐页碰运气,改成**字段差分审计**:把前端实体的每个字段,与服务端
实际写入(INSERT 列)和读取(映射函数)的字段做差分。

上一版的 `parent_id` 就是这样漏掉的(前端有、服务端存不了)。同一方法一次扫完
交易 / 账户 / 分类 / 订阅 / 负债 / 投资 / 持仓历史 / 目标,直接把孤儿字段列出来。

负债命中:前端有 `entryMode` / `simpleDueDate` / `simpleAmount`,而

| 环节 | 情况 |
| --- | --- |
| `ledger_debts` 表 | 没有对应列 |
| 写入(21 列 INSERT) | 三个字段都不在其中 |
| 读取映射 | 同样没有 |
| 备份格式 | 也没有 |

三个值在往返中全部蒸发。

### 改法

只加列,不动既有约束:

- `relationalDatabase.js`:建表加三列;**schema v7 → v8**,`ADD COLUMN` 给已有库补列
- `relationalDataRepository.js`:写入带上三列(占位符 21 → 24),读取映射回三个字段

`iconUrl` **故意不加**:`resolveDebtIconUrl` 会用 `findDebtPreset(name)` 按名称兜底,
属于可推导的缓存值 —— 不把设计取舍当成 bug 修。

### 验证

走真实写入路径(GET bootstrap → 追加简单负债 → POST import)后:

- 库中该行:`entry_mode='simple'`、`simple_due_date='2026-12-20'`、`simple_amount=777`
- 其余负债三列均为 null(不会凭空写上简单模式字段)
- 重新加载页面,该负债渲染为 **「还款提醒 | ¥777.00 | 2026-12-20 | 待处理」**
  —— 修复前这里是 ¥0.00 + 待补日期

自动化:新增用例断言三字段能存进库并读回,并确认完整模式负债不会被写上这些字段。
**临时还原修复后确认该用例会失败**。本地库已自动迁移到 v8。

### 本轮一并审计过、结论是「不动」的地方

- **投资持仓历史**:服务端不存 `positionName` / `category` / `platform` / `fundCode` /
  `holdingShares` / `isActive`,刷新后 `positionName` 会退化成「未命名持仓」。
  但全仓**没有任何组件渲染这些字段**,唯一影响是备份里的名字 —— 为了没有可见收益的
  字段再加一次迁移不划算,记录在此待定
- **设置层**:`ledger_user_settings` 的 11 个 key 齐全且都有真实数据(智能预算 1.3KB、
  AI 消息 12KB)
- **AI 设置 / 调试日志**:走 localStorage,其中 API key **有意不跨设备同步**,不是缺陷
- **智能预算的额度分配**(住房 ¥206 而房租 ¥6,500,界面报「超支 >999%」)属于
  **产品建模问题**:用户已单独声明「固定支出 ¥3,000」,住房却仍被放进灵活预算池按权重分配。
  这需要产品决策,不擅自改预算算法
