## 三处「界面给出的结论和事实对不上」

这一版 1 个提交,修的是同一个毛病:**界面给了看起来正常的结论,而事实不是那样**。

### 一、固定支出是一笔看不见的钱

「固定支出 ¥3,000」原先只从可支配收入里**减掉**,却从不落到任何分类上:

- 它不出现在「分类预算执行」里
- 它不进任何合计
- 于是汇总卡上「已经用掉 ¥744.51 / 执行率 15% / 健康度 100」被读成「整体很稳」

而房租——这个月最大的一笔支出——**压根没进过账**。用户实际当月花掉 ¥8,669,
总预算只有 ¥7,900,页面上却一切正常。

**改法**

- `buildBudgetTrackingRows` 补一行「固定支出」合计:
  预算取用户自己声明的数额,已花取所有**刚性分类**(住房 / 还款 / 保险 /
  税费 / 水电燃气 / 通讯)的当月合计
- 汇总卡的「灵活分类合计」改成「固定 + 灵活」—— 它现在确实含固定支出了
- 点「固定支出」的「查看详情」会聚合全部刚性分类的明细,否则只有一个空列表

演示账本上的变化:

| | 修复前 | 修复后 |
| --- | --- | --- |
| 本月预算 | ¥4,900 | **¥7,900**(固定 + 灵活) |
| 已经用掉 | ¥744.51 | **¥7,887.82** |
| 固定支出 | 不显示 | **¥7,143.31 / ¥3,000,超 ¥4,143.31** |
| 分类超支 | 0 | 1 |

### 二、超支 238% 被判成「预算执行得很稳」

健康度只数「几个分类超支」,一个超到 **238%** 的分类和刚过线 1% 的扣一样的分:
90 分、**状态优秀**、结论写「预算执行得很稳,可以把结余优先安排到储蓄或应急金」
—— 而同一屏下方就写着「月底预计超支 ¥2,388.46」。

**改法**:除按个数扣分外,再按**超出的倍数**追加扣分,并在明细里写明最多超了多少。

修复后同一屏:62 分 / **需要留意** / 「还有收紧空间,优先从超支分类里压降。」
其中「分类超支 1 个分类超出预算,最多超了 138%  −38」。

### 三、这个抽屉关不掉

打开「查看详情」后,右上角的 ✕ **点不动**,只能刷新页面。

原因是层叠顺序:抽屉 `z-index: 80`,而粘性顶栏是 `220` —— ✕ 正好落在顶栏覆盖的
区域里,`document.elementFromPoint` 命中的是 `workspace-topbar`。而这个抽屉
**既没有点背景关闭,也没有 Esc 关闭**,✕ 是唯一的出口。

**改法**:`.sb-drawer` 的 `z-index` 80 → **250** —— 压过顶栏(220)和右键菜单(240),
仍低于确认弹窗(260),不会挡住弹窗。

### 四、顺手修掉明细里的两个显示问题

- **交易日期直接渲染原始值**,页面上是 `2026-11-08T07:09:03.839Z`;
  改用全站统一的 `formatDate`,现在显示 `2026/11/8`
- **金额符号写死成「-」**:退款在 `budgetDetail` 里已经是负数,拼出来是
  **`--¥390.55`**;改成按正负给 `+` / `−`,实测退款显示 `+¥390.55`

### 仍然记录在案、没有动的

- **「执行节奏 100%,节奏可控  −0」**:执行率刚好不到 1,所以不扣分,
  但同一个卡片的节奏预测已经提示「月底预计超支 ¥2,388」。这是 12 天前就用完
  整月预算的形态,把节奏预测接进健康度打分是下一步
- **用户声明的 ¥3,000 远低于实际刚性支出 ¥7,143**。这一版让这个落差第一次
  **可见**了,但算法不该替用户改数字 —— 该由用户决定是提高固定支出、还是压降房租
