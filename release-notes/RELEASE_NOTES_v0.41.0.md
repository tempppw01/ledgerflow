## 账单导入与金额的正确性

这一版 4 个修复全在「金额」与「账单导入」上,共同点是**用户看不出来的错**:
要么账写错了日期/方向,要么整行被悄悄丢掉,界面上都显示「导入成功」。

### 1. 认不出的日期被写成「今天」—— 整份账单落到同一天

`parseDate` 解析失败时会 `return new Date().toISOString()`,也就是今天。

| 输入 | 修前 | 修后 |
| --- | --- | --- |
| `2026年11月18日 09:30`(中文日期) | 记成 **今天** | 正确解析为 2026-11-18 |
| 完全认不出的时间 | 记成 **今天**,无提示 | 整行跳过(计入 skipped) |

中文日期尤其致命:很多银行导出的时间列就是「2026年11月18日」,于是**整份账单落到导入当天**,
月统计、趋势、预算全部错位。

现在支持中文日期/时间(`年月日`、`时分`)与 `2026.11.18`、`2026/11/18`;认不出来时区分两种情况:
**整份账单没有日期列** → 沿用「记到今天」的兜底;**有日期列但这一行认不出** → 整行跳过。

### 2. 退款行被记成收入 —— 凭空多出一笔收入

支付宝把退款记在**同一行**:金额 24.59、成功退款 24.59、状态「退款成功」。这行的经济含义是**净额 0**,
但旧逻辑有两条路把它变成收入:「成功退款 > 0 就判收入」,以及「状态/商品名里含『退款』也判收入」。

| 行 | 修前 | 修后 |
| --- | --- | --- |
| 支出 24.59 / 退款 24.59 | **收入 24.59** | 不产生记录(净额 0) |
| 支出 100 / 退款 30 | **收入 100** | 支出 **70**(按净额) |

一行就能让账错 2×金额。现在:**收支列能读出「支出/收入」时以它为准**,退款列只用于把
全额退款(净额 0)剔掉、部分退款折成净额;只有收支列是乱码时才用退款列兜底判收入。

### 3. 全角数字与币种代码的金额让整行被静默丢掉

| 金额单元格 | 修前 | 修后 |
| --- | --- | --- |
| `５８.００`(全角) | NaN → **整行丢弃** | 58 |
| `CNY 58.00` / `RMB58.00` | NaN → **整行丢弃** | 58 |

现在会折算全角数字、剥离人民币写法。**外币符号与代码刻意不剥**(`$`、`USD`):这个账本只有人民币,
把「$1,234.56」当成 ¥1,234.56 记进去比跳过更糟 —— 这类行保持跳过。

### 4. 取整算法统一到一处

项目里曾并存 `Math.round(v*100)/100` 与 `Math.round((v+EPSILON)*100)/100` 两套,`1.005` 会分别得到
**1.00** 与 **1.01** —— 同一笔钱在不同模块差一分。现在只有 `shared/lib/money.ts` 一套
(负数 `.5` 远离零、`-0` 归一、幂等),14 个文件的内联取整全部改为调用它。
