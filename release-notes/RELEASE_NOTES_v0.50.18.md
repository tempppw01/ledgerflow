## 删掉订阅生成的那笔支出,续费日不退 —— 再生成就整整跳过一期

这一版 1 个提交,**含一次数据库结构升级(v9)**。

### 症状

演示账本 iCloud+ 200GB(¥21/月,基线续费日 2026-11-28)实测:

| 步骤 | 续费日 |
| --- | --- |
| 基线 | 2026-11-28 |
| 第 1 次「生成支出」 | 2026-12-28(记了 1 笔) |
| **删掉那笔生成的流水** | 2026-12-28 ← **没退回** |
| 第 2 次「生成支出」 | **2027-01-28** ← 整段 12 月被跳过 |

钱是对的(只记了 1 笔),但**日程默默少了一期** —— 而「续费日」同时驱动
「续费已逾期」提醒和首页的资产负债预测,于是 12 月那一期再也不会被提示。

### 根因:又是「成对数据只做了一半」

```
generateSubscriptionTransaction   推进续费日一期,并记下 lastGeneratedTransactionId
removeTransaction                 对订阅什么都不做        ← 没跟上
```

去重点只认「同一天 + 同账户 + 同金额」,所以删掉再生成必然走成新的一期,于是日期被推进两次。

### 改法:把「推进前」的日期存下来,删除时精确还原

- **没有用「倒推一期」** —— 日期推算是**夹过月尾**的(1月31日 +1月 = 2月28日),
  从 2月28日 倒推只能得到 1月28日,那等于换一个新的月末漂移。
- `ledger_subscriptions` 增加两列 `prev_renewal_date` / `prev_expire_date`
  (**schema v9**,走既有的版本化迁移,升库幂等);生成时存快照;
  `removeTransaction` 发现被删的正是某订阅 `lastGeneratedTransactionId` 指向的那笔时,
  退回日期、清空快照与引用、按退回后的日期重算状态。
- 顺带覆盖「先给订阅支出退款、再删原交易」这条路径:级联删掉的同样是那笔生成的流水。

### 验证

- 新增 **4 条回归测试**(退回上一期、再生成只推进一期、**月末 1月31日精确还原**、
  删无关流水时日期不动)。把退回逻辑去掉,前三条即失败,其中第二条报的正是
  `expected '2027-01-28' to be '2026-12-28'`
- 浏览器实测(真实升到 v9 之后):基线 2026-11-28 → 生成 2026-12-28 →
  **删掉流水退回 2026-11-28**(快照清空、状态重算为「即将到期」)→ 再生成 **2026-12-28**

### 升级说明

首次启动会自动把 `ledger_subscriptions` 加上两列(幂等,可重复执行);
没有这两列时应用照常工作,只是「删除后不退回日期」的旧行为会保留到升级为止。

### 仍然需要你拍板(第六次提出)

`isExpenseLike`(支出 + 预算 + 还款)与首页的 `isActualExpenseType`(支出 + 还款)对
**「预算」型交易**判断相反:记一笔 ¥100 的预算型交易后,页头「本月结余」减 100,
而「钱都去哪了」各分类合计不变。这是口径清单里唯一没收敛掉的一项。
