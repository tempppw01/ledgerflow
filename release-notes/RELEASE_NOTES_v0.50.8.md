## 撤销 AI 助手登记的还款,本金会凭空多出一笔

这一版 1 个提交。继续在**还款管理**这条线上找「动钱」的问题。

### 背景:还款记录里为什么要存快照

登记一笔还款会同时改两处:写一条还款记录,并把负债的本金 / 期数往前推。
所以**删除记录时必须把这两处一起还原**,否则本金会永久性对不上。

拿什么还原?记录里存了一份「登记前的本金 / 期数」快照(`balanceBefore` /
`paidPeriodsBefore` / `remainingMonthsBefore`)。没有快照的旧数据只能估算,
而估算分支是这样的:

```
balance = debt.balance + amount
```

### 症状

这份快照是靠**调用点自己记得传**的:

- 还款管理页 —— 传了 ✓
- **助手那条路径 —— 没传** ✗

于是助手登记的还款只能走估算分支。还款金额超过剩余本金时(登记时余额被夹到 0),
估算就把超出部分也算进了本金:

```
负债剩 ¥100,还了 ¥150  →  登记后余额 0
撤销这笔还款           →  0 + 150 = ¥150      ← 应为 ¥100
```

**用户凭空多出 ¥50 的负债。** 反方向(少算本金)是用户占便宜,这个方向是白背债。

### 改法

不指望每个调用点都记得传,**让 store 自己补**:

两个调用点都遵循「先 `addRepaymentRecord`、再 `updateDebt`」的顺序,所以
`addRepaymentRecord` 执行时 `state.debts` 里读到的正好就是扣减前的值。在这里补齐快照,
以后新增调用点也不会漏。

- 调用方显式传的值仍然优先(`balanceBefore ?? ...`,保留显式的 0)
- 找不到对应负债时行为不变:仍走估算分支,且不抛错

### 仍然记录在案、没有动的

- **历史记录没有快照**:演示库和早前版本写下的还款记录 `balance_before` 全为 null,
  撤销它们仍走估算分支。要修得靠数据迁移或让用户在 UI 上手工校正 —— 这一版不动老数据
- 助手路径**记住的是它自己算的 nextBalance**,而页面路径用的是同一套公式;
  两处公式目前一致,但将来若分叉,`updateDebt` 那一侧仍需要一处共用实现
