## 修:余额变动页,备注过长会把界面撑开

### 根因不是"没写省略号",而是**列宽由内容决定**

那一列本来就有 `overflow: hidden; text-overflow: ellipsis; white-space: nowrap` ——
但表格是 `table-layout: auto`,**列宽由内容撑出来**。于是一条 180 字符的备注(订单号那种
没有空格的串)把「说明」列顶到 **1284px**,整张表 **1670px**,页面被撑开。

在 auto 布局下,`ellipsis` 和 `overflow-wrap` 都不会解决问题 —— 列本身已经变宽了。

顺带发现同一处还有个隐藏问题:说明文本在一个 `inline-flex` 按钮里,却**没有 `min-width: 0`**,
所以即使列宽被限制,省略号也不会生效(flex 子项不会被内容压缩)。

### 改了什么

| 位置 | 改动 |
| --- | --- |
| 表格 | 改 `table-layout: fixed`,并按列分配宽度(时间 15% / 账户 14% / 类型 9% / 变动 15% / 余额 17%,说明列吃剩余) |
| 说明文本 | 补 `min-width: 0`,让省略号真正生效 |
| 备注小字 | 任意位置可断行 + 最多两行 + 超出省略 + `title` 悬停看全文 |
| 表格单元格 | 兜底 `overflow-wrap: anywhere`,任何一格都不会被不可断行的长串顶宽 |

### 验证(真实长备注实测)

临时账号导入一笔备注为 `NZ999…`(182 字符)的支出,在余额变动页测量:

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 表格宽度 | **1670px** | **929px**(容器可见 930px) |
| 说明列宽 | **1324px** | **279px** |
| 文本是否截断 | 否(整条撑开) | **是**(省略号生效) |
| 页面横向溢出 | 0(但表格自身横向滚动) | 0,且表格不再超宽 |

截图确认:长备注被截成 `NZ99999999…`,各列对齐、金额右对齐,表格正好占满容器。

前端 1194 项 / 160 文件、服务端全过、九道闸门 + 演示库基线全 0。

### 说明

CSS 布局问题没有单测可写 —— 这条用的是**实测数值 + 截图**证据(修复前后各测一次)。
用户可控文本所在列用固定宽度,是这类"长内容撑破表格"的通用解法。
