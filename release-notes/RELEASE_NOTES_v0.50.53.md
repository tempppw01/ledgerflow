## 修:「上传微信账单失败」还有一个漏网的情况

### 怎么发现的

上次修完「wps 里日期是 Excel 序列号 → 解析 0 条」(v0.50.44),我验证用的是**你发来的那份微信账单**,
它**能正常导入**。这轮我想做一次端到端验证,于是**自己造了一份同结构的 xlsx**(openpyxl 生成):
前置 17 行、表头、6 条数据(含 1 笔中性交易)、日期同样是序列号。

结果:**解析出 0 条,跳过 6 条** —— 和你最初报的症状一模一样。

### 根因:日期还原只认"没有 t 属性的数字"

xlsx 里单元格的写法有两种:

- 微信自己导出的文件:`<c r="A19" s="1"><v>46350.78…</v></c>`(**没有 `t`**)
- openpyxl / LibreOffice 这类工具:`<c r="A19" s="1" **t="n"**><v>46350.78…</v></c>`(**显式标了数字**)

而上次的修复写的是 `} else if (!cellType) {` —— **只处理没有 `t` 的那种**。所以微信官方导出的账单能导入,
**而用别的工具另存/转换过的账单仍然 0 条**。

### 改动

```ts
} else if (!cellType || cellType === 'n') {
```

一行。但这一行决定了"日期能不能被还原",也就决定了整份文件能不能导入。

### 验证

用那份合成账单跑完整链路(现在它是仓库里的 fixture):

| 金额 | 分类 | 日期 |
| --- | --- | --- |
| 39.70 | **餐饮** | 2026-11-24 18:46 |
| 3.50 | **交通** | 2026-11-23 18:03 |
| 53.00 | **医疗** | 2026-11-22 22:46 |
| 50.00 | **购物** | 2026-11-21 10:00 |
| 100.00 | **收入** | 2026-11-20 09:00 |

- **5 条**入库,**中性那笔 500 被跳过**(skippedCount = 1)
- 日期是**真实日期**,不是 `46350.78…`
- 分类**全对**

**证伪**:把那一行改回 `!cellType` → 解析回到 **0 条 / 跳过 6 条**,测试失败;还原后通过。
