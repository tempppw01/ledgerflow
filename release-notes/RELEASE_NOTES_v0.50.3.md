## 分类重名:两个「什么都没发生」的坑一起补掉

这一版 2 个提交,都是「界面给了正常的反馈,实际却没按用户以为的方式执行」。

### 一、新建重名分类:表单清空,什么都没创建

在「账户与分类」里输入一个**已经存在的同级分类名**(比如已经有「餐饮」,
再打一次「餐饮」),按回车——

- 输入框**被清空了**,看起来像成功了
- 不报错、不提示、也不 toast
- 但分类列表一条都没多

原因是 store 对「同名 + 同父级」是**静默复用**(直接返回已有分类的 id),
而界面拿到的返回值和真正新建时一样,于是照样清空输入框。

行内「+子分类」走同一条路径,同样中招。

**改法**

- store 抽出 `findDuplicateCategory`,导入 / 助手 / 界面共用同一条重名规则
  (归一化空白 + 小写比较),不再各写一份
- 顶部表单与行内「加子分类」都先判重:重名时提示
  **「分类「餐饮」已存在,换个名字试试。」**,并**保留已输入的名字**,
  不用重新打字

### 二、改名撞名:两个同名分类,下次载入时静默合并

把「午餐外卖」改成已存在的「其他」,界面上立刻出现**两个「其他」**,
没有任何提示。下次载入时 `sanitizeCategoriesAndTransactions` 会把它俩
**静默合并**,被合并那个分类下的交易也跟着换了归属 —— 用户完全不知情。

把子分类挪到一个**已经有同名子分类**的上级下面,是同一个问题的另一条入口。

**改法**

- `findDuplicateCategory` 增加 `excludeId`,判重时排除正在编辑的这一条
- 改名与换上级统一在保存前判重:撞名时提示,并**停在编辑状态**,
  改个名字就能继续
- `.category-action-error` 改为独占一行 —— 原来它和表单挤在同一行,
  一句「分类「X」已存在」被压成 150px 宽的三行窄条,读起来比没有还费劲

### 验证

都在真实浏览器里复现过,也都在真实浏览器里确认修好:

- 建重名分类:输入框保留「餐饮」,下方红字提示,分类数不变
- 建不重名的分类:正常创建,输入框清空(没有把正常路径一起拦掉)
- 改名撞名:停在编辑状态 + 红字提示,分类数不变;取消后数据完好
- 编辑行无报错时高度仍是一行(62px),`flex-wrap` 没有撑高布局

自动化:新增 **4 条**回归测试(一级重名、子分类重名、改名撞名、换上级撞名)。
**逐条临时还原修复后确认会失败**,恢复后全绿。

### 仍然记录在案、没有动的

- **智能预算的额度分配**:住房 ¥206 而房租 ¥6,500,界面报「超支 >999%」。
  `rateDisplay.ts` 已经把百分比封顶在 999%(这份封顶是**故意的**:超支几十倍时
  「超支 ¥6,294」才是读者要的信息)。真正的问题是**产品建模** ——
  用户已单独声明「固定支出 ¥3,000」,住房却仍被放进灵活预算池按权重分配,
  而住房 / 还款 / 税费 / 保险 这类**刚性支出**本不该参与灵活额度分摊。
  这需要一次产品决策,不擅自改预算算法
- **投资持仓历史**的部分字段(服务端不存,但没有任何组件渲染)保持原样
