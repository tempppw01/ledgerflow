## 「本月可投资现金」有两份实现,两处都错、错法还不一样

这一版 1 个提交。

### 症状

同一个概念在两处各写了一遍,而且**都错,错法还不同**:

| 位置 | 问题 |
| --- | --- |
| 投资理财页 | 按月取交易(对),但**没排除退款** —— 退款被当成又花一笔 |
| 投资助手聊天面板 | `月收入 − Σ(全部历史支出)` —— **没有月份过滤** |

后果(演示账本,登记月收入 ¥26,000):

| | 本月支出 | 可投资现金 |
| --- | --- | --- |
| 修复后 | ¥7,764.37 | **¥18,235.63** |
| 投资页旧逻辑 | ¥8,545.47(多算 2×390.55 = ¥781.10) | ¥17,454.53 |
| 聊天面板旧逻辑 | — | **¥0.00** |

聊天面板那个是**硬错**:任何用满一个月的账本,「本月可投资现金」都恒为 0
(26,000 − 十几万 → 负数 → 被 `Math.max(0, …)` 夹成 0),而这个值正是喂给 AI 投资分析
的输入之一。

### 改法

把这个概念收成一份实现(`src/features/investments/model/monthlyCashflow.ts`):
按月取(本地月)、排除不计入余额的状态、退款/冲正抵减、合计走共享的 `summarizeTransactions`。
投资页与聊天面板都改为调用它;顺手删掉投资页里因此变成死代码的 `getMonthBounds`。

### 验证

- 新增 4 条回归测试(退款抵减 / 只算本月 / 不计入余额的状态不算 / 无月收入回落净额)。
  **三个缺陷各自证伪一次,每条都精确失败**:
  - 退款不抵减 → `expected 1400 to be 600`
  - 不过滤状态 → `expected 1000 to be 100`
  - 不按月份过滤 → `expected 131000 to be 1000`
- 真实数据交叉验证(见上表)
- 前端 **1112 项 / 147 文件**、服务端 **42 项**;`tsc` 0、`eslint` 0、i18n 两闸门 0、
  `check:dates` 0、`check:money` 0、`check:shared-predicates` 0
