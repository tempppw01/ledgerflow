## 明细页可用性、金额一致性、以及一批性能优化

这一版包含 8 个提交:2 个性能优化、3 个 bug 修复、2 个页面重构、1 个交互改进。

### 1. 财务分析页:两段分析其实**永远不会显示**(根因修复)

```ts
if (tx.adjustmentKind) return false;   // ← 真值判断
```

`TransactionAdjustmentKind = 'normal' | 'refund' | 'reversal'`,而 store 在规范化时会给
**每一笔**交易写上 `adjustmentKind: 'normal'`。于是这一句把所有普通交易都当成调整行排除:

| 区间 | 页头「支出」 | 「过去」段 |
| --- | --- | --- |
| 本月 | ¥7,887.82 | 日均支出 **¥0.00** / 最大分类 **未分类** / 「还没有足够的支出分类样本」 |
| 近30天 | ¥12,056.62 | 同上 |
| 近90天 | ¥43,380.35 | 同上 |

同一页一边显示「支出 ¥12,056.62」一边显示「日均支出 ¥0.00」;消费习惯推断、可压缩支出信号、
消费者画像也全部退化成占位文案。修后(近30天):日均支出 **¥414.91**、最大分类 **住房**、
复盘结论「住房是当前分析周期支出最高的分类,占比约 52.2%。另外发现一笔偏大的支出:11 月房租。」。

同页另外三处:区块标题被粘性顶栏遮住(加 `scroll-margin-top`)、资金看板增减值没有标签
(那其实是「较上月」)、三组快动作按钮全叫「继续处理」(改成一行自解释按钮)。

### 2. 余额变动明细:整页重构

进页面实测 299 条明细只有 **403px 高、210 个字符** —— 三组默认收起,一屏只有三个折叠头。

- **汇总口径修正**:原分组统计只覆盖「当前页的 50 条」却看起来像全局统计;现在顶部四格
  (净变动/增加/减少/笔数)是**筛选后的全部**口径。实测自洽:198,819.40 − 96,147.11 = 102,672.29。
- **一屏 4 条 → 10 条**:大卡片换成紧凑表格(时间/账户/类型/说明/变动/变动后余额),点击行展开细节。
- **按天分组**:分组头吸顶并给出当天小计;只有一条记录的那天不占表头。
- **新增筛选**:关键字/类型/账户/时间,写进 URL。
- 空态区分「没有记录」与「筛选无结果」。

### 3. 订阅管理:死药丸 → 可点筛选

顶部四个状态统计是 `<article>`,**点不动** —— 看到「已到期 2」想点进去看那两条没有任何反应;
而下面又用 3 张提醒卡把同样内容再说一遍。

- 药丸变成筛选按钮(`aria-pressed`),点「已到期」清单 3 条 → 2 条
- 提醒卡组压成一行(名字都保留)+「只看待处理」,**222px → 一行**
- 每张卡从 4 个常显按钮(含红色删除)收敛为「生成支出」+「⋯ 更多」
- 新增表单默认收起,收起时清单独占整行;**整页 1461px → 900px(一屏内)**

### 4. 分类:两级折叠更好用

折叠本来就有,但唯一入口是 11px 的 `▾` 字符(**实测墨迹仅 9px**),命中区 30×20;
折叠状态还不持久。现在有子分类时**整块主区可点**(命中区 **158×28**),箭头用 CSS 画
(收起旋转 90°),状态写进本地。此前折叠功能**零测试覆盖**,已补 4 项。

### 5. 金额格式:同一页两种写法

还款管理页概览卡用 `formatCurrency`(**¥12,860.40**),而负债列表与详情面板是手写的
`¥{x.toFixed(2)}`(**¥12860.40**);列表那处更是 `toFixed(0)`。共修 **24 处**
(还款页 12 + 助手页 12,含一个共享 helper)。

**新增闸门 `npm run check:money`**(已接入 CI):扫 JSX 里的 `¥{…toFixed(…)}`。
接入前它自己就抓出了助手页 9 处漏网 —— 这正是加它的意义。

### 6. 性能与交互

- **写操作路径**:排序键预计算,单次写 76.6ms → **47ms**(1 万条存量)
- **交易列表排序**:**5.2×**(19.9ms → 3.8ms),比较函数里不再解析日期、不再重复做中文比较
- **助手页进入时直接落在最后一条**:容器 CSS 写了 `scroll-behavior: smooth`,而 `behavior: 'auto'`
  会沿用 CSS 值 —— 必须显式用 `'instant'`,并在绘制前(`useLayoutEffect`)落位
