## 修:新用户想导入账单,**找不到入口**

### 怎么发现的

本来想做「导入链路」的端到端验证:把一个**新账号**打开交易页看看。结果发现空状态的文案写着

> 📋 暂无交易记录
> **添加第一笔交易,或导入账单数据。**

而**整页没有任何导入入口** —— 我把所有按钮、链接的文本、`aria-label`、`title` 都扫了一遍,
搜「导入 / import」**零命中**。当时页面上只有「新增账目」。

原因:「导入账单」按钮放在「**当期账单**」那一排 `.transactions-current-bill-actions` 里,
**没有任何交易时那一排根本不渲染** —— 于是新用户被文字引导去导入,却**无路可走**。
支付宝那条入口也是一样(同一排)。

### 改了什么

| 位置 | 改动 |
| --- | --- |
| `EmptyState`(共享组件) | 新增**可选**的 `secondaryActions`,向后兼容;原有单/双动作用法不变 |
| `TransactionTable` | 空列表时给出**两个**导入入口:「导入微信账单」「导入支付宝账单」(不传则不显示) |
| `TransactionsPage` | 把 `openImport` 传下去 |

**为什么不合并成一句"导入账单"**:`source` 决定交易标签(微信导入 / 支付宝)和一条支付宝专属解析规则 ——
合并成一个不选来源的按钮,会把支付宝账单当成微信账单解析。所以两个来源分开给。

### 验证(浏览器实测)

修复后,同样一个**新账号**的交易页空状态变成三个动作:

> 📋 暂无交易记录 · 添加第一笔交易,或导入账单数据。 · **导入微信账单** · **导入支付宝账单** · 新增账目

**需要说明的**:点进去之后的**完整导入链路这次没有走完** —— 文件选择器弹出了、文件也递进去了,
但我在处理中间弹窗时把流程取消了,所以**数据库里没有这次导入的记录**。
因此本次验证的是「入口出现了」,不是「导入成功」;导入本身的正确性由 1253 项测试里的
账单解析测试与上一版的真实文件验证(0 条 → 445 条)覆盖。

前端 1253 项 / 167 文件、服务端全过、十一个闸门 + 演示库基线全 0。
