## 修:「主题色」被写死成琥珀 —— 六套配色只有一套生效

### 怎么发现的

接着上一轮那条线索(找「声明了但没实现」的空壳)继续扫,这次换了个更本质的判据:
**接口里声明、但 store 之外完全没人用过的方法**。79 个候选里过滤掉解构调用的误报后只剩 2 个,
其中一个就是 `setAccentTheme`。

翻到 `App.tsx` 就看到原因了:

```ts
document.documentElement.setAttribute('data-theme', resolvedTheme);
document.documentElement.setAttribute('data-accent-theme', 'amber');   // ← 写死
```

**主题色被硬编码成 `amber`** —— 也就是说:设置里存的那个值(默认也是 amber)**无论存什么都会被覆盖**,
而 `tokens.css` 里六套 `[data-accent-theme='…']` 配色**只有琥珀那一套真的被用上**。

配套的东西其实全都做好了:`AppAccentTheme` 类型(6 个值)、`tokens.css` 六套变量、
连选择器的样式类(`.settings-accent-grid` / `.settings-accent-option`)都写好了 ——
**只差"应用它"和"让用户能选"**。和分类学习是同一类问题。

### 改了什么

- `App.tsx`:`data-accent-theme` 改为读设置里的值(依赖数组也补上,改主题色立即生效)
- 设置页「偏好」标签里加了**主题色选择器**:6 个选项,每个带一个色点,选中项高亮
  (复用已有的样式类,只补了色点与选中态的 CSS)
- 中英文案:琥珀 / 蓝 / 翠绿 / 紫罗兰 / 玫红 / 极光

### 验证(浏览器实测)

| 偏好设置 | `data-accent-theme` | `--color-primary` |
| --- | --- | --- |
| 默认 | `amber` | `#f59e0b` |
| 翠绿 | `emerald` | **`#10b981`** |
| 玫红 | `rose` | **`#f43f5e`** |

主题色**真的会变了**(修复前无论存什么都是 `#f59e0b`)。
