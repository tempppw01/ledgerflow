## 新:关于页的「最近更新」—— 版本记录 + 中文说明

关于页原来只有当前版本号和一个「检查更新」按钮 —— 版本号背后的那些改动,
在这个应用里**看不到**。这一版补上最近 10 个版本的记录:版本号、发布日期、标题、
中文摘要,每条都能点到对应的 GitHub Release。

### 一、数据从哪来:两条现成的路都被排除

| 方案 | 为什么不成立 |
| --- | --- |
| 前端直接 `import` `release-notes/*.md` | `release-notes/` 被 `.dockerignore` 排除,**镜像里根本没有这些文件**,Docker 构建阶段就会失败 |
| 运行时请求 GitHub API | 给"打开关于页"加上网络依赖与限流;页面里本来只有**用户主动点**的「检查更新」会联网 |

结论是**生成 + 提交**:`release-notes/*.md` → `src/pages/about/recentReleases.generated.ts`。
这跟仓库里 `generate-changelog.mjs` → `CHANGELOG.md` 是同一个套路,区别只在于产物要
在浏览器里渲染,所以必须是 TS 而不是 markdown。

### 二、抽取规则(**没有**任何"大概意思"的加工)

| 字段 | 取法 |
| --- | --- |
| 标题 | 第一个 `## ` 行(去掉行内 markdown) |
| 摘要 | 标题之后**第一段散文** —— 跳过标题/表格/列表/引用/代码块 |
| 日期 | 对应 tag 的创建日期 |

两条规则是量出来的,不是猜的:

- **摘要不能只看"标题后面那段"**。116 份说明里有约三分之一是「标题 + `### 小标题` + 正文」
  的结构(标题下面直接跟小标题),必须继续往下找第一段散文。
- **中文硬换行不能直接 `join(' ')`**。这些说明是按中文硬换行的,拼起来会在中文标点后面
  多出一个空格 —— 实测过「…还有多久结束、 下一段…」就是这样来的。现在只在**两侧都是
  拉丁字符**时补空格。
- 摘要在 150 字处按整句截断(句末落在前半段就硬切加省略号);段落后面紧跟表格/列表/
  引用时,说明这句话只是"引子",收尾补省略号 —— 否则会留下「这轮撞的是 CSV 的几个
  脏情况:」这种**悬空冒号**。

### 三、闸门是"重新生成再比对",不是抽查

`npm run check:release-history` 重新生成一遍再**逐字节比对**,并且已经接进 CI 的静态
一致性那一步。理由:这里真正的风险是**整体过期**(新增了版本却没重新生成、改了标题没
同步),抽查只能证明抽到的那几条恰好对 —— 而"页面显示的是上一个版本的内容"这件事,
界面上完全看不出错。

另外 `recentReleases.test.ts` 钉住一条最容易烂的性质:**第一条必须是当前版本**
(`RELEASE_HISTORY[0].version === APP_VERSION`)。版本号改了却忘了重新生成时,
这条测试直接红。

### 四、日期里有个"先有鸡还是先有蛋",以及一条要说清的局限

发布流程是「写说明 → 提交 → 打 tag」,**生成数据的那一刻,最新版本的 tag 还不存在**。
所以生成器把这种情况先按**当天**写入并在输出里点名提醒,打完 tag 再跑一次就校准成
tag 的真实日期。

**局限(写进文档了,不要当成已覆盖)**:CI 的 checkout 默认 `fetch-depth: 1`、不取 tag,
那里的日期一律**沿用已提交值** —— 也就是说"日期写错"只会在本地被抓到。

### 五、页面本身

- 区块放在版本信息之后,顺序是「当前版本 → 检查更新 → 最近更新 → 项目与原则」。
- **不加 `aria-live`、不加 `role="status"`**:静态列表不需要被读屏反复播报(和盘前盘后
  倒计时那条取舍同源)。
- 当前版本单独打一个「当前版本」标记,日期用 `<time datetime="…">` 输出。
- **英文界面下标签与标题跟着语言走,数据保持中文原文**,并在说明里写清"发布说明是
  中文撰写" —— 不做假翻译,也不假装这些说明是英文的。
- 脚注写明数据来源与"随应用一起打包,不联网获取"。

### 六、顺手修:纯日期在 UTC- 时区会渲染成前一天

`new Date('2026-11-27')` 会被当成 **UTC 零点** —— 在 `America/New_York` 渲染成
11 月 26 日。发布日期正好是纯日期,踩上去就是「v0.51.0 发布于 11 月 26 日」。
新增 `formatIsoDay`,对纯日期补**本地**零点,并把这条性质写成带阳性对照的测试
(测试里先证明"直接解析确实会差一天",再证明修好的实现不差)。
