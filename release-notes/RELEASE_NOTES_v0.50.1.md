## 电子钱包账户消失了:一份写在前、类型补在后的白名单

这一版 1 个提交,修的是一类很容易重演的缺陷:**白名单写在前,新类型补在后**。

### 症状

「账户与分类 → 资金账户」只列出 3 个账户,而库里实际有 6 个:
**支付宝、微信钱包、招商银行信用卡全部缺席** —— 看不到、改不了名、也删不掉。

实测那个账本里,300 笔交易有 **240 笔(80%)** 就挂在这些「看不见」的账户上。
它们能被「记一笔」选中、能正常记账,却在管理页面上消失。

### 根因

页面用一份白名单过滤要展示的账户类型:

```ts
const GENERAL_ACCOUNT_TYPES: AccountType[] = ['cash', 'debit', 'savings', 'virtual'];
```

这份白名单写于 **2026-02**,当时的重构把 credit / liability / receivable 移到还款页
统一管理 —— 所以不含它们是有意的。

而 **`ewallet`(电子钱包)是 2026-11-22 才补进域类型**的,为的是让演示数据里
`type: 'ewallet'` 的账户不再让备份校验整份失败。白名单写在那之前,自然不认识它。

### 改法

把 `ewallet` 加进白名单,并在注释里写清两件事:**credit / liability / receivable 是有意排除的**,
以及 **ewallet 为何必须包含** —— 免得以后有人看到「为什么只列这几种」又把它改回去。

### 为什么过去的测试没抓到

原有测试的 fixture 把支付宝 / 微信写成 `type: 'virtual'`(在白名单内),
恰好掩盖了这个问题;真实数据用的是 `ewallet`。

新增用例显式构造 `type: 'ewallet'` 的账户,断言它出现在资金账户列表里、
且类型标签是「电子钱包」而不是原始英文枚举。**临时还原修复后确认该用例会失败**,
证明它抓的正是这个 bug,而不是走过场。

### 验证

- 浏览器:资金账户 **3 → 5**,支付宝 / 微信钱包带「电子钱包」标签与品牌图标出现;
  信用卡仍按设计留在还款页
- 全站 UI 体检:36 项检查 0 问题(确认这一批改动没有引入布局回归)
- 前端 **1066 项 / 141 文件**、服务端 **37 项**
- `tsc` 0、`eslint --max-warnings=0` 0、i18n 两闸门 0、`check:dates` 0、`check:money` 0

### 本轮一并排查过、确认没有问题的

- **标签重命名 / 合并**:两者都正确持久化,合并后交易数不变、无孤儿标签行
- **回收站恢复分类**:只放回分类、不恢复交易归属 —— 但删除时已明确告知交易归入
  「未分类」,属于设计取舍而非缺陷
- **交易状态列**:300 笔里 4 笔无状态(历史数据),当前代码路径(手动、助手)
  都会写入 `completed`,不必改
