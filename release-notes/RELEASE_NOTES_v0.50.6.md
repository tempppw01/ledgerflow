## 健康度接上节奏预测:11 月 23 日就用完整月预算,不再叫「节奏可控」

这一版 1 个提交。修的是上一版留下的最后一处自相矛盾。

### 症状

同一张预算卡片上,四行结论互相打架:

```
分类超支   1 个分类超出预算,最多超了 138%        −38
执行节奏   整体用掉预算的 100%,节奏可控            −0
收支平衡   收入可以覆盖本月支出                    0
按现在的节奏,月底预计超支 ¥2,388.46。
```

执行率是 99.8%,**不到 1**,所以「执行节奏」一分不扣,还写着「节奏可控」。
可同一张卡片下方已经算出:**月底会超 ¥2,388**。当天是 11 月 23 日,这个月还剩 7 天
—— 整月预算早已花光。这不是可控,只是「还没超过 100%」这个数字游戏。

### 原因

健康度只看**已经发生**的执行率,完全不看节奏预测。而 `calculateBudgetPacing`
早就算出了 `projectedSpent` / `projectedOverspend`,只是没喂给打分。

### 改法

- `calculateBudgetHealth` 新增可选入参 `projectedExecutionRate`:按当前节奏外推到
  月底的执行率。**传了就按它判节奏**;不传退回 `executionRate` —— 历史月份里
  `projectedSpent === totalSpent`,两者等价,所以已有调用与测试不受影响
- 页面把 `pacing.projectedSpent / overview.totalBudget` 传进去(pacing 的计算挪到
  health 之前,否则引用未初始化的 `const`)
- 明细文案要连 **key** 一起换,不能只换 fallback:旧 key 在语言包里已经有值,
  `tf()` 优先取语言包 —— 只改 fallback 的话外推文案根本不会出现
  (**这一条是我先在浏览器里看到「整体已用掉预算的 130%」才发现的**,自测用例当时
  用的是纯 fallback 的 translator,所以没暴露)

### 修复后同一张卡片

```
当前预算缺口明显,建议立刻调整超支分类的额度。
分类超支   1 个分类超出预算,最多超了 138%            −38
执行节奏   按现在的节奏,月底预计用掉预算的 130%      −15
收支平衡   收入可以覆盖本月支出                        0
按现在的节奏,月底预计超支 ¥2,388.46。
```

健康度 **62 → 47**,结论从「需要留意」变成「**存在风险**」—— 和「已经超支 ¥4,143、
月底还要超 ¥2,388」的事实对上了。

  而不是「整体已用掉」。**临时还原后确认会失败**

### 至此,智能预算这条线上不再有「界面说没事、账上其实有事」的地方

按时间倒着修过来:

1. 住房被塞进灵活池分到 ¥206 → 刚性支出不再参与灵活分摊(v0.50.4)
2. 固定支出从不进任何合计 → 补成一行合计,超支看得见(v0.50.5)
3. 超支 238% 与 101% 扣一样的分 → 按超出倍数追加扣分(v0.50.5)
4. 已用 100% 仍写「节奏可控」 → 接上节奏预测(v0.50.6)

### 仍然记录在案、没有动的

- **用户声明的固定支出 ¥3,000 与实际刚性支出 ¥7,143 差了一倍多**。落差现在完全可见,
  但算法不该替用户改数字 —— 是提高固定支出、还是压降房租,该由用户决定
- 「执行节奏」在**历史月份**仍按实际执行率判定,这是对的:历史月份没有「外推」这回事
