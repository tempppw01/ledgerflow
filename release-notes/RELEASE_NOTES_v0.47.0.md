## 数据完整性:备份里的东西终于齐了

这一版 6 个提交,核心是一条线 —— **备份"成功"但数据不全**,以及两处读数别扭的修正。

### 1. 负债与还款记录根本不在备份范围内(换设备后静默丢失)

`debts` / `repaymentRecords` 存在偏好 store 里,而本地 JSON 备份的载荷**完全没有这两块**,
备份范围也只有四类。后果:导出 → 换设备 → 导入,界面提示「恢复成功」,但**负债与还款历史全部消失**。

修复:备份范围新增「负债与还款」(默认勾选),载荷新增两块,恢复时写回 store 并同步到服务端。

### 2. App 自己导出的备份,**自己导不回来**

做端到端验证时撞出来的:

```
备份文件字段无效:data.accounts[2].type 枚举值不合法
```

演示数据里支付宝/微信钱包的 `type` 是 `ewallet`,而 `AccountType` 联合类型里没有这个值
(全项目源码 0 处引用),导入校验用同一个集合判断 → 硬失败。

- 补齐域类型:`ewallet`(标签「电子钱包」、图标 👛)
- **校验改为宽松**:认不出的类型不再让整份备份失败(落成 `undefined`,其余字段照常导入)
  —— 一个不认识的枚举值不该让人完全无法恢复数据

### 3. 偏好与计划纳入备份,JSON 与云端快照终于一致

对照云端快照发现还有一批"云端有、文件没有":`smartBudgetPlan` / `smartBudgetHistory` /
`categoryLearningRules` / `categoryLearningEvents` / `creditDrafts` / `forecastBills` /
`monthlyIncome` / `rssSubscriptions`。

新增一个 `preferences` 范围组(默认勾选),载荷里对应**一个对象**而不是十几个平铺字段。

**关键守卫**:旧备份没有这个字段时,解析保持 `undefined`、应用回退当前值 ——
否则一次「导入旧文件」会把现有偏好清空(第一版实现就是这样,被新写的测试当场抓住)。

### 4. 新增「恢复后自检」

`verifyFinanceBackupRestore()`:恢复完成后把「备份里写了多少条」与「真正落到状态里的有多少条」
比一遍,少了就告警**哪一组、差几条**,而不是只说"成功"。

### 5. 两处读数别扭

- **智能预算**:「还能花 **-¥2,987.82**」→ 超支时标签改成「**已超支 ¥2,987.82**」;
  「今天约 -¥373.48」→「今天已超 ¥373.48」
- **执行率 3155.3%** → 超过 999% 封顶显示 `>999%`(数学没错,但四位数百分比没有信息量)

### 6. 投资理财页文案瘦身

11 条解释性长句压成一句(周末休市 60 字 → 17 字、持仓排序说明一整句 → 一行标签、
板块公式去掉从句……),原则是**留口径、压操作说明**。该页文本 1948 → 1636 字符。
