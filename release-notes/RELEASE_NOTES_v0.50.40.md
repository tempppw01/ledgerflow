## 设置页新增两项:默认打开页面、本位币

设置里多了一个「偏好」标签,放两件事。

### 一、默认打开页面

打开应用时直接进入你常看的那一页(首页 / 交易流水 / 财务分析 / 智能预算 / 投资理财 / 还款管理等)。
**只在这一台设备上生效**(和主题一样),换设备不受影响。

两条行为细节:

- **每次打开应用只跳一次**。之后你在侧边栏点「首页」,看到的就是真正的首页,不会被反复弹走 ——
  实现上用模块级标记(刷新后归零),而不是组件状态(组件会随路由卸载重挂)。
- 判断放在 effect 里读 store 的当前值。放在渲染期读会有水合时序问题:首屏渲染时持久化可能还没恢复出来,
  结果就是「设置明明存着,刷新却不跳」—— 这个坑实测踩过。

### 二、本位币(账本计价单位)

可选 12 种货币,影响**金额的符号与小数位规则**。语义是「这个账本的数字以什么货币计」:

- **不做汇率换算** —— 把本位币从人民币切成美元,屏幕上的数字不变,变的只是它们被标成什么货币
  (这正是你选的方案);
- **随账本同步**,所有设备一致(不像默认打开页面那样只存本地);
- 简写金额(`1.23万` / `1.2K`)也跟着换符号 —— 原来那里把 `¥` 写死了;
- 英文界面下仍是短符号 `¥`,不会出现 `CN¥`(这是原代码注释里就警告过的事)。

### 实现过程中修掉的三个真问题

| 问题 | 怎么发现的 |
| --- | --- |
| 服务端把两个参数塞进了同一个 `setSetting(...)` 调用,而它只收 4 个参数 —— **多的被静默忽略**,`base-currency` 从来没写进库 | 浏览器实测:改了币种、刷新后回到 CNY ✗ → 查库发现没有那一行 |
| 渲染期读 store 导致的水合时序问题(见上) | 设置存着但刷新不跳 ✗ |
| 默认页面选项里引用了不存在的键 `nav.repaymentManagement` | `i18n:check` 直接报「代码引用但资源缺失」✗ |

### 验证

- 本位币格式化 6 条新测试(符号、数值不变、简写、英文短符号、非法值忽略、€/JPY);
  **证伪**:把 `formatCurrency` 改回写死 CNY → USD 那条立刻失败
- 浏览器端到端:偏好标签渲染两项 → 切 USD → **刷新后仍是 USD**,首页金额显示 `$`、不再有 `¥`
- 浏览器端到端:设置默认页为 `/transactions` → **全新加载落到 `/transactions`**;
  之后点侧边栏「首页」→ 正常回到首页并显示仪表盘(不重复跳转)
