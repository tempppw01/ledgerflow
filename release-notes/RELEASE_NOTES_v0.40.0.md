## 分类身份只用 id

应用允许**同名子分类**共存(「餐饮 / 其他」与「交通 / 其他」),但好几处代码拿**显示名**
当身份用。名字只是展示用的,一旦当主键,重名就会静默算错 —— 这一版把这类问题收干净。

### 1. 财务分析:同名子分类被合并成一行(占比算错)

分类聚合以名字为 key:

```ts
const key = getCategoryName(item.categoryId, categories, messages);
acc[key] = (acc[key] || 0) + amount;
```

| 数据 | 修前 | 修后 |
| --- | --- | --- |
| 「餐饮/其他」100 + 「交通/其他」300 | 一行 `其他 400` | 两行,各 100 / 300 |

金额、占比、分类图与「最大分类」判断一起偏。改为按**分类 id** 聚合,显示名用「父 / 子」区分。

### 2. 首页分类图:同一问题 + 两处硬编码 + 暴露内部 id

- 同样按名字聚合 → 同名子分类合并,环形图配色与占比跟着错
- 未分类兜底是字面量 `'未分类'`、汇总桶是字面量 `'其他'` → **英文界面露中文**
- 分类已删除但引用还在时,图上直接显示一串 **id**

改为按 id 聚合、显示名统一计算、汇总桶走 i18n(`dashboard.categoryBreakdown.other`),
并处理「真实分类也叫『其他』」的撞名(用父分类区分,不与汇总桶同名)。

### 3. AI 重分类:交给模型的名字列表本身有歧义

「AI 重分类」把 `categories.map(c => c.name)` 直接塞进提示词,回来后按名字 `find`:

1. 模型看到**两个一模一样的「其他」**,无从区分
2. 返回后 `find` 只命中**列表第一个** → 可能把「交通」的支出记到「餐饮」下
3. 没有任何提示,用户只会觉得 AI 分类不准

现在提示词里给的是 `餐饮 / 其他`、`交通 / 其他` 这种无歧义名字,回来走**唯一索引**;
拿不到唯一 id 就交给 fallback,**不猜**。

### 一处收口

新增 `src/shared/lib/categoryLabels.ts` 作为分类显示名的**唯一实现**:

- `buildCategoryLabels`:同名加「父 / 子」前缀,唯一名保持原名
- `buildCategoryLabelIndex`:能唯一确定分类的名字列表 + 名字 → id 映射;
  加前缀后仍重名的**不进映射**

首页分类图改用同一实现,避免两处规则各自漂移。

### 备注:同类风险的排查结论

「用显示名当身份」这一族到此**基本扫完**。剩下两处看着像同类其实是**故意的启发式**:
账户名匹配微信/支付宝(`workbenchMapping`、`importAccount`),以及标签按字符串统计
(标签本身就是字符串,重名合并是语义正确的)。
