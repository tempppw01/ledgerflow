## 直接访问 /login 登录后,落在「这个页面不存在」

这一版 1 个提交。

### 症状

登录表单是 `AuthGate` **就地**渲染在当前路径上的,而 `/login` 并不是应用路由
(`src/app/router/router.tsx` 里只有通配 404)。登录成功后 `AuthGate` 只 `setUser(...)`,
**不做任何跳转** —— 于是 URL 仍是 `/login`,路由落到通配 404:

```
访问 /login → 输入正确账号密码 → 登录成功 → 页面显示「这个页面不存在」
```

刚输完密码却看到这个,只会以为登录失败。

### 严重性:我先高估了,随后自己推翻

我最初写成「每个用户首次登录都会撞到」,**这个判断是错的**:

- 未登录时打开根路径 `/`,登录表单就在 `/` **就地**渲染,登录后 URL 不变、一切正常;
- 应用内部**没有任何链接指向 `/login`**(全仓搜不到 `'/login'`)。

所以只有**手动访问 `/login`** 的人(书签、凭印象敲地址)会遇到 —— 不是普遍问题,但确实是个死胡同。

### 改法

登录/注册成功后,若当前路径是 `/login`,整页跳回 `/`。用整页跳转而非 `useNavigate` 的理由
写在注释里:`AuthGate` 的测试是不套路由直接渲染的,引 `useNavigate` 会让整套夹具都得包一层;
而这个分支只发生在「手动访问 /login」这条冷路径上,代价可忽略。

### 验证

- **修复前**:访问 /login → 登录 → URL 停在 /login、页面 404
- **修复后**:访问 /login → 登录 → URL 变成 `/`、正常渲染(本月结余 ¥1.86万 / 净资产 ¥29.6万)
- 常规路径回归:在 `/` 登录仍然正常
- `AuthGate` 7 项、前端 **1140 项 / 152 文件**、服务端 **45 项**;`tsc` 0、`eslint` 0、
  六道闸门 0、`audit:ledger-math` 通过

### 顺带:新用户不是「空的」

为验证这条路径我建了测试用户,发现它**首次登录后自带默认数据**:11 项设置、2 个账户、20 个分类
(交易为空)。所以「空账本」实际是「有默认账户/分类、没有交易」—— 这才是新用户的真实起点。
页面在这种状态下渲染正常(¥0.00、有「还没有任何账目记录」的空状态提示)。
测试用户已按依赖顺序清理干净,无残留。

### 一次自我修正

我用生成器脚本改 `AuthGate`,替换结果变成了字面量 **NaN** —— `String.prototype.replace`
把替换串里的 `$` 序列当成了特殊模式(与此前几次「模板串里嵌反引号」同类)。文件被改坏后
改用 edit 工具手工修回,再全量验证。**教训:要写含引号/反引号/`$` 的内容,直接用 edit 工具。**
