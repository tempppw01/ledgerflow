## 分类推断:补上真实商户名的关键词

上一版把「按行推断分类」接进账单导入之后,还有一个决定成败的细节:**关键词覆盖**。
用一批真实商户名一测,就露出 5 个明显缺口 —— 而且全都落到「支出」这种兜底分类上:

| 账单里的文本 | 改前 | 改后 |
| --- | --- | --- |
| 稻家乐社区**厨房** | 支出 ✗ | 餐饮 |
| 兰州牛肉**面馆** | 支出 ✗ | 餐饮 |
| 沙县**小吃** | 支出 ✗ | 餐饮 |
| 好利来**烘焙**坊 | 支出 ✗ | 餐饮 |
| 大参林**药房** | 支出 ✗ | 医疗 |

原因很实在:原来的餐饮词表是围绕「餐/饭/外卖/火锅/奶茶」写的,而真实账单里大量商家用的是
**厨房、面馆、小吃、烘焙坊** 这类说法 —— 一个「餐」字都不含。医疗那边只认「药店」,不认「药房」。

### 改了什么

**餐饮**补:厨房、饭店、饭馆、餐厅、面馆、米线、米粉、小吃、烘焙、西点、面包、蛋糕、卤味、串串、排档
**医疗**补:药房、购药、口腔

纯追加,不动原有词序 —— 所以既有测试一条没影响。

### 验证

新增 `categoryKeywords.test.ts`:20 个真实商户名 + 3 个收入场景,**表驱动**断言名字 → 分类。
失败时会直接告诉你哪个商户词没覆盖。

- 改前:**5 条失败**(报错就是上表那五行的 `expected '支出' to be '餐饮'` / `'医疗'`)
- 改后:**23 条全过**
- 前端 1219 项 / 162 文件、服务端全过、九道闸门全 0

这条测试的价值不在"现在对不对",而在**下次再加关键词时不会踩坏已有的**。

### 仍然存在的边界

推断是**关键词**驱动的,认不出来的商家会落到默认分类(而不是硬塞一个错误分类)—— 这是有意的:
宁可让用户自己改,也不要悄悄记到错的类里。真正想提升覆盖率,下一步应该是**从用户的修改里学习**
(项目已有 `categoryLearningRules` 这套机制,只是账单导入还没用上)。
