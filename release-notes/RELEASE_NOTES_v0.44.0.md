## 一致性:日期归属、跨页选择、跨实体引用

这一版修的三个问题都是「同一个概念在不同代码路径上有不同口径」,另外补了两套防护。

### 1. 日期:还剩 8 处「按 UTC 取日」

`date.slice(0, 10)` 取的是 **UTC 日**,而用户在编辑页选的是本地时间。在 UTC+8 的
本地 00:00–07:59,一笔「今天」的账会被算到昨天:显示成昨天,还会掉出「本月」筛选。

上一版只修了交易页与助手页,这次把剩下的 8 处收干净:

| 位置 | 影响 |
| --- | --- |
| `billImport` 导入去重身份 | **与页面的判定口径不一致**(我上一版只改了一边,重复导入会漏判) |
| `quickAddSummary`「今天的支出」 | 凌晨记的账不算进今天 |
| `semanticRecall` / `workbenchUtils` | 语义召回与工具入参按 UTC 取日 |
| `BillPreviewCard` 预览显示与表单值 | 预览里显示的日期可能差一天 |
| `assistantAgentTools` 查询区间(4 处)与 `update_transaction` | AI 查询/改写的日期边界 |

现在 `src` 里**没有任何 `date.slice(0, 10)`**。

**新增闸门** `npm run check:dates`:命中即非 0 退出,并提示改用 `resolveTransactionLocalDay()`;
允许显式白名单(须写明「为什么这里按 UTC 是对的」)。

### 2. 跨页勾选后导出/打印只包含当前页 —— 「已选 4 条」只导 2 条

勾选是**跨页**的:翻页不清空、工具栏显示的是**总数**、批量删除也按总数走。
但导出 PDF / 打印 A4 用的是 `viewRows.filter(...)` —— 只有当前页。

浏览器实测:

| 步骤 | 工具栏 |
| --- | --- |
| 第 1 页勾 2 条 | 已选 2 条 |
| 翻到第 2 页(选择仍在) | 已选 2 条,本页 0 条被勾 |
| 第 2 页再勾 2 条 | **已选 4 条** |

此时导出只有 2 条,另外 2 条**静默丢失**。现在改为从整份筛选结果里取,与批量删除统一。

### 3. 订阅绑定的账户被删后照样写流水(悬空引用)

`subscription.accountId || accounts[0]?.id` 只看「填没填」,不看「账户还在不在」。
账户删掉后仍会写出一笔流水:`computeAccountBalances` 匹配不到账户 → 余额里看不到,
却出现在交易列表与支出统计里。现在会显式校验并拒绝,提示「请先重新指定账户」。

### 配套的防护

- **`npm run check:dates`**:禁止按 UTC 取日(见上)
- **随机操作扫描扩到负债与还款记录**(另一个 store):5 种操作 × 200 步,
  检查「还款记录必须指向存在的负债」等不变量;顺带确认**删负债会连带删掉还款记录**
- 两套扫描都带**覆盖率断言**(确认真执行了各类操作)与**反向验证**(人为造脏数据,
  检查器必须报出来)—— 一个恒真的检查器没有价值
