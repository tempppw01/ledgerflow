## 新:美股盘前 / 盘后 —— 标记 + 倒计时

行情卡片上早就有「盘前 / 盘后」这两个字,但**没有时间感**:看不出这一段还有多久结束、
下一段什么时候开始、现在是周五晚上所以要等到下周一。这一版把它补齐。

### 一、先说清楚"这一段到底是什么"

美股指数**本身没有**盘前/盘后这两段交易 —— 后端是用对应的 ETF(如 SPY)代替的,
所以原来的卡片上必须显示 ETF 代码。这次补的倒计时沿用同一个窗口定义:

| 时段 | 美东时间 | 说明 |
| --- | --- | --- |
| 盘前 | 04:00–09:30 | 正在进行时数到 **09:30** |
| 常规 | 09:30–16:00 | 这一段原有逻辑不变 |
| 盘后 | 16:00–20:00 | 正在进行时数到 **20:00** |

判定全部按 `America/New_York` 的当地分钟数做,夏令时交给 `Intl` 换算 ——
3 月和 11 月的切换发生在周日凌晨,本来就不在交易周内,不需要特殊处理。

### 二、三个状态,以及一个必须算对的地方

每个时段有三种状态,倒计时指向**不同的目标**:

| 状态 | 含义 | 倒计时数到 |
| --- | --- | --- |
| 进行中 | 这一段正在交易 | 本段**结束** |
| 距开始 | 今天还没到点 | 本段**开始** |
| 距下个盘前 / 盘后 | 今天已经过去了 | **下一个交易日**本段开始 |

那个"必须算对的地方"是:**周五收盘之后不能按 18 小时算**。
周五 17:00(美东)如果只加一天,得到的是"周六凌晨 4 点盘前"—— 市场根本没开。
实测:

| 时刻(美东) | 盘前倒计时 | 盘后倒计时 |
| --- | --- | --- |
| 周五 08:30 | 进行中 · 剩余 **01:00:00** | 距开始 07:29:59 |
| 周五 17:00 | 距下个盘前 **58:59:59** | 进行中 · 剩余 02:59:59 |
| 周一 10:00 | 距下个盘前 **17:59:59** | 距开始 05:59:59 |
| 周六 13:00 | 距下个盘前 **38:59:59** | 距下个盘后 50:59:59 |

最后一行的周六:两个倒计时都指向下周一,并额外说明「周末休市,两个倒计时都指向下个交易日」。
小时数刻意不取模到 24 以内 —— **56:00:00 就是 56 小时后**,写成 08:00:00 才是误导。

### 三、**刻意不做**的一件事:节假日

倒计时**没有**自己的节假日表,只按周一~周五算交易日。理由是仓库里唯一的节假日数据
(`MARKET_HOLIDAY_NOTICES`)只有几个中国节日与圣诞,而市场开闭市的判定
(`getGlobalMarketState`)本身也只按工作日。倒计时如果自己另搞一套,就会出现
**页面说「未开盘」、倒计时说「还有 2 小时开盘」**这种自相矛盾 —— 宁可少一个功能,
不要两块互相打脸的界面。

### 四、时间轴上的窄段:不用"更浅的同色"区分

扩展时段也画到了 24 小时轴上。区分方式**不是**把同一颜色调浅:只改透明度的话,
在低对比主题与色觉障碍下,它会跟常规时段糊成一条。改成**上下各收 2px 的窄轨**
(常规 8px、扩展 4px)—— 高度差是不依赖颜色的第二重线索,颜色只是补充。

### 五、无障碍上的两个取舍

- **不加 `aria-live`、不加 `role="timer"`**。里面每秒都在变,加了就是每秒对读屏器
  播报一次倒计时,那是最典型的过度播报;读屏用户移到这一段时会读到当时的值,足够了。
- **状态写在文字里**(进行中 / 距开始 / 距下个盘前),小圆点和边框色只是视觉提示,
  **不靠颜色或圆点传达信息**。

数字用等宽数字(`tabular-nums`)并且实测了宽度稳定性:3 秒里倒计时走了 3 秒,
文字宽度 **148.45 → 148.45px**(不变),否则每秒重排会让整行左右抖。
阳性对照是同位置换成 Georgia:宽度 55.91 → 57.73,说明这个量具真的能量出差异。

### 六、顺带修:时间轴刻度在窄屏互相压字

量倒计时的时候发现的既存问题:`/investments` 的 24 小时刻度是 7 个绝对定位的 `<span>`,
视口越窄越挤。

| 视口 | 改前 | 改后 |
| --- | --- | --- |
| 480 / 430 / 414 / 390px | 正常 | 完全一致 |
| 375px | `00:00↔04:00`、`20:00↔24:00` 间距 **-0.5px**(已经贴住) | 只标 00 / 08 / 16 / 24 |
| 360 / 320px | 压掉 **6.7px**,`04:00` 盖住 `00:00` 的尾数 | 同上,不再重叠 |

被盖住的是**数字**,读出来是错的时刻 —— 不只是"不好看"。修法是 380px 以下隔一个标一个。

### 七、新致败项 `overlappingLabels`,以及它第一版的失败

判据:同一父级下两个 `absolute`/`fixed`、**自己直接写了文字**的元素,包围盒在 x 与 y 上
都重叠 > 1px(刻意收得紧,免得把未读小红点、头像角标这类"故意叠"的设计算进来)。

**这条检查第一版是坏的**:时间轴默认折叠,不点开那 7 个 `<span>` 根本不在 DOM 里,
跑完 69 个组合一条都不报 —— **不是没问题,是它没在看**。这和 `focusWalk`
第一版只跑桌面档是同一类错误。补了 `expandDisclosures()`:先量折叠态,
干净就把 main 里名字像「展开 / 更多 / 显示」的开关点开(最多 3 个)再量一遍。

破坏性验证(把 `display: none` 注释掉):

| 状态 | 结果 |
| --- | --- |
| 放回缺陷,跑 `--mobile` | 退出码 1,`reflow-320 /investments` 报 `00:00↔04:00 9.7x12.4px`(与独立探针一致) |
| 还原 | `overlappingLabels` 0 条 |
