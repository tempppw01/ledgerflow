## 预算为 0 的分类:显示「超支」,却写着「执行率 0.0%」

这一版 1 个提交。

### 症状

把一个分类的预算改成 **0**,然后在这个分类里有支出,那一行会自相矛盾:

```
修复前  餐饮  超支 · 已花费 ¥333.29 · 预算 ¥0.00 · 执行率 0.0%      ← 超支却是 0%
修复后  餐饮  超支 · 已花费 ¥333.29 · 预算 ¥0.00 · 执行率 >999%      ✅
```

同时「已超支」计数从 1 变成 2(判定本来是对的)。

### 根因

```
ratio:      budgetAmount > 0 ? spent / budgetAmount : 0     ← 零预算被固定成 0
isOverspent: diff > 0                                       ← 这一支判对了
```

两个字段对同一行的结论相反。而这条**真的能走到**:预算编辑器允许把分类预算改成 0
(`BudgetCategoryList` 判断的是 `next >= 0`)。

值得注意的是,`formatExecutionRatePercent` 里**早就写好了 `Infinity → >999%` 的分支**,
却没有任何代码会产生 Infinity —— 这一支显然就是当初漏掉的一半。

### 改法

- 零预算且有支出时,`ratio` 记为 `Number.POSITIVE_INFINITY`(「无上限」),由既有的
  格式化分支渲染成 `>999%`;
- 另有两处**直接乘 100** 渲染(智能预算的 AI 突出提示、预算向导表格)改为走共享的
  `formatExecutionRatePercent` —— 否则接入 Infinity 后会打印出「Infinity%」;
- 两个进度条用 `Math.min(…, 160/100)`,Infinity 会被夹成满格,无需改动。

### 验证

- 新增 2 条回归测试(零预算+有支出 / 零预算+无支出)。**把 `ratio` 改回 0 的旧写法,
  第一条即失败**(`expected +0 to be Infinity`)
- 浏览器实测:把餐饮预算改成 0 → 该行变为「超支 / >999%」、已超支计数 1→2;
  改回 ¥539 → 恢复「正常 / 61.8%」;库里预算方案也已核对回原样
- 前端 **1114 项 / 148 文件**、服务端 **42 项**;`tsc` 0、`eslint` 0、i18n 两闸门 0、
  `check:dates` 0、`check:money` 0、`check:shared-predicates` 0

### 记录在案、本轮不动

`row.ratio` 在预算模块里有**五处**各自渲染:整数 %(AI 面板)、一位小数 %(列表/抽屉)、
`>999%`、以及两处进度条上限分别是 160 与 100。这是显示精度取舍,不是算错;
要不要统一成一套是产品口味 —— 我不擅自改。
