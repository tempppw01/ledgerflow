## 新用户的第一个画面:先是「没数据」,然后才是「记第一笔」

这一版 2 个提交。一个修的是新用户看的第一眼,一个是把死代码清掉。

### 1. 空账本首页:45% 的篇幅在展示"没有数据",而该做的事排在最后

用「有账户、零流水」的新账号走了一遍首页,量出来的是:

| 指标 | 实测 |
| --- | --- |
| 页面总高 | **1844px** |
| 「¥0.00」出现 | **13 次** |
| 资产负债预测面板 | **684px** |
| 未来与待办 | **154px** |
| 引导卡位置 | 第 4 个区块(**页面最底部**) |

那两个面板加起来 838px(45%),全在展示"没有数据":一条平折线加 30 格全 0 的日历、
「预计余额最低日 11月23日 ¥0.00」这种没有信息量的读数。而空状态引导卡**本来就有**
(312px 的 `EmptyState`)—— 问题只出在顺序与冗余渲染:**第一个真正该做的事排在最后。**

改法:

1. 没有可预测内容时,不渲染「资产负债预测」与「未来与待办」两个面板
2. 引导卡移到 hero 之后(原来在页面最底部)

判据是「没有可预测的东西」:流水、负债、订阅都为空。

> 第一版我用「账户数为 0」当判据,**没生效**(页面只从 1844 降到 1500)。
> 原因是注册流程本来就会建好账户与分类,所以从未记账的新账号是「有账户、零流水」——
> 按账户数判断正好漏掉这类。真正决定预测面板是否有意义的是流水/负债/订阅,不是账户。

| 指标 | 修复前 | 修复后 |
| --- | --- | --- |
| 页面总高 | 1844px | **910px**(−51%) |
| 「¥0.00」出现 | 13 次 | **7 次** |
| 资产负债预测 | 684px 空图表 | 不再渲染 |
| 未来与待办 | 154px「暂无安排」 | 不再渲染 |
| 引导卡 | 第 4 位 | **第 2 位(hero 之后)** |

有数据的账号行为不变:两个面板照常显示、引导卡不出现。

### 2. 删掉整份无人使用的 `useUIAnimations`(362 行 / 5 个 hook)

排查定时器泄漏时发现的:上一版清理「延迟清除状态」的定时器时只判断了
「同文件里有没有 `clearTimeout`」—— 那是个弱信号。补了配对核对后发现真正漏掉的那处
(`useButtonFeedback` 的 400ms 涟漪清除)就藏在 `src/shared/hooks/useUIAnimations.ts` 里,
而**这个文件整份都没人用**:362 行、5 个导出、全项目零 import、零测试,
最后改动是 2026-04-05,7 个多月未动。

修它不如删它 —— 留着只会等某天有人 import 进来,把那个缺陷一起带进来。
需要时 `git show f14b128:src/shared/hooks/useUIAnimations.ts` 可随时取回。

### 3. 顺带修掉一个反复踩的环境缺陷

排查过程中 `data/backups/` 里复制 SQLite 又让 dev server 崩了一次:

```
Error: EBUSY: resource busy or locked, watch '...data\backups\...sqlite'
```

`vite.config.ts` 的 watcher 忽略清单只有 `**/*.tmpdir/**`,而 `data/` 是本机运行时目录。
**watcher 不看 .gitignore**,所以备份一个正被后端打开的 `.sqlite` 副本就会抛 EBUSY
并终止 dev server —— 表现是"备份完数据库,dev server 莫名挂了"。这个坑踩过两次。
已加 `**/data/**`,并实测验证(再备份一次,dev server 依然存活)。
