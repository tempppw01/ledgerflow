## 「分类学习」曾经是个空壳 —— 现在真的能用了

### 发现

上一版我说「项目已有 `categoryLearningRules` 这套机制,只是账单导入还没用上」。**这句话不准确** ——
我这次把实现翻开看,发现它**从来没有被实现过**:

| store 方法 | 改前 | 改后 |
| --- | --- | --- |
| `suggestCategoryByLearning` | `() => null` | 按规则匹配,返回分类与置信度 |
| `recordCategoryCorrection` | `() => {}`(noop) | 落规则 + 记事件 |
| `undoLatestCategoryLearning` | `() => false` | 撤销最近一次学习 |

而**管道全都建好了**:数据模型、备份与还原、多设备同步、设置页的文案与导出字段 —— 只有逻辑是空的,
而且**没有任何地方调用**它们。典型的「看起来有、其实没做」。

### 现在怎么工作

1. 你把一笔交易的分类从 A 改成 B → store 记一条规则(按「商户名」这个 token);
2. 之后导入账单或新增同类交易时,**先问规则、再问关键词**(规则代表你自己的习惯,优先级更高);
3. 设置页的「撤销最近一次分类学习」现在真的能撤销。

**token 的归一化**(决定匹配准不准):去掉括号里的分店名、去掉数字与标点、全角转半角、丢单字。
这样「稻家乐社区厨房(寮步坑口店)」与「稻家乐社区厨房」能匹配上,而订单号不会污染匹配。

### 改了什么

- 新增 `shared/lib/categoryLearning.ts`:纯函数核心(token / 建议 / 记录)**11 条测试**
- store 里三个空实现换成真实现;**改分类时记录**接在 `updateTransaction` 上(唯一该触发的地方)
- 账单导入把规则接在**关键词之前**;`categories` 与 `categoryLearningRules` 都从文件级入口转发到行级
- 顺手合并了一个重复定义:store 里原本另有一份同结构的 `CategoryLearningRule`,已改为引用同一个定义

### 验证

- 前端 1233 项 / 164 文件、服务端全过、九道闸门 + 演示库基线全 0
