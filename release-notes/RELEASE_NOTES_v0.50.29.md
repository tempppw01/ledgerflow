## 离线记的账,关掉页面就没了 —— 而且事后毫无痕迹

这一版 1 个提交。

### 症状

账本数据**不在浏览器里持久化**:财务 store 用的是 `sqlOnlyStorage`,一个刻意的空实现
(`getItem → null`、`setItem → undefined`)。这是多用户隔离之所以干净的原因 —— 但代价是
**任何还没推到服务端的改动只活在内存里**。

实测(临时账号):

1. 断网 → 记一笔 ¥666 → 界面显示它,并给出常驻提示「云端同步失败:Failed to fetch」;
2. 恢复联网 → 刷新页面 → **界面和数据库里都没有 666**,提示也一并消失。

用户**无从知道**那笔没了 —— 刷新后应用看起来一切正常。对照:同一会话里在线记的那笔,
刷新后还在。

### 改法(只加保护,不改任何数据语义)

新增 `shared/hooks/useUnsyncedChangesGuard.ts`:有未同步改动时挂 `beforeunload` 监听,
离开页面前让浏览器弹确认框。gate 维护 `hasUnsyncedChanges` —— 本地一变置真,推送成功置假,
失败(含 id 冲突暂停)保持真。

它**不修复**「离线记账」本身:那需要本地队列 + 重放 + 冲突处理,属于另一个量级的改动,
而且与上一版记下的「整份快照会覆盖别人写入」共用同一套设计。这一版只把
**静默丢失**变成**用户明确选择**。

### 验证

- 新增 3 条 hook 测试(有改动要拦 / 无改动不许拦 / 同步完成后撤掉监听)+ gate 原有 2 条
- 浏览器实测**两个方向**:
  - 断网记 777 → 刷新 → **浏览器确认框真的弹出**(Playwright 收到 beforeunload dialog)✓
  - 在线记 888 → 等同步完成 → 刷新 → **没有确认框**,888 存活 ✓
- 前端 **1143 项 / 153 文件**、服务端 **45 项**;`tsc` 0、`eslint` 0、六道闸门 0、`audit:ledger-math` 通过

### 顺带:PWA 配置本身是干净的(未改动)

- `navigateFallbackDenylist: [/^\/api\//]` —— API 请求不走 Service Worker 回退,
  不会拿缓存页面顶替接口响应;
- `skipWaiting + clientsClaim + cleanupOutdatedCaches` —— 新版本立即接管,
  避免旧 chunk 造成「加载不全」;
- 运行时只缓存 CDN(R2)的字体与图片,且都有条数/时长上限;**没有缓存任何 API** ——
  所以不会出现「离线看到旧账本」。

### 一个小瑕疵(未改,记录在案)

同步失败提示把浏览器原文 `Failed to fetch` 直接显示在中文界面里:
「云端同步失败:Failed to fetch」。
