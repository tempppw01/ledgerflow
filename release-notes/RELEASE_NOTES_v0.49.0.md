## 概览页的「门面」,以及一个再也别靠肉眼找问题的体检工具

这一版 3 个实质提交(`v0.48.0..v0.49.0`),一条线:**把只能靠人眼发现的问题,变成可复跑的东西。**
两个界面改动都是先在浏览器里实测出来、再动代码。

### 1. 概览页 hero 重做:补留白、填右侧空档、文案年轻化

反馈是「不够高级、缺少留白、文案不够年轻化」。量完发现是三件事叠在一起:

**留白不是"留得不够",是空间没被用。** 卡片 1052px 宽,内容只占左半边约 465px,
**右侧约 700px 完全空着**。根因是它被做成一条纵向长条:

```css
padding: clamp(24px, 4vw, 38px) 0 clamp(22px, 3vw, 30px);   /* ← 左右内边距就是 0 */
```

内容直接顶到容器边缘。改动:

- 改成三栏:**文案 / 两个关键数字 / 操作**,横向把空间真正用起来
- 「插画 + 两个数字」编成一组(readout)—— 它们是同一个读数视觉组
- 补足四边内边距;从「页头 + 一条底边线」改成有自己表面的卡片(边框 + 16px 圆角 + 微投影)
- 关键数字 18–24px → 22–30px,成为这一屏真正的视觉重心

**插画被压成了一块小色块。** 素材是 undraw 的**方图 839×880**,却塞进 132×72 的扁框,
`contain` 之后只剩 72px 高,夹在标题与数字之间既不是装饰也不是信息。改为按方形摆放(72–96px)。

**文案:**

| 原 | 现 |
| --- | --- |
| 今天也适合把账说清楚 ✨ | 今天记了吗 |
| 今天的钱花在哪、还剩多少、哪里能省一点,这里直接告诉你。 | 本月的收支、结余和去向,一屏看完。 |
| 夜深了,注意休息,LedgerFlow | 夜深了,注意休息,睡前顺手记两笔 |
| 试试深色模式,在侧边栏底部的主题切换器中选择 | 夜间用深色更顺眼,顶栏右上角可切 |
| 你可以在记账助手中粘贴账单截图,AI 会自动识别并生成记账数据 | 账单截图丢给助手,自动变成记账数据 |

- 新增 `getGreetingAction()`:按时段给一句「今天能做什么」,第一行终于有内容可读
  (原来只有时间问候,信息量为零)
- 产品名不再缀在问候语后面 —— 它在侧边栏、标题、关于页已经出现过三次
- 6 条提示全部收短;顺带清掉变成死键的 `dashboard.ui.welcome`

**加栏必须同时想好窄屏(这次踩到了):** 第一版只写桌面四栏、没有降级,390px 下四栏被硬挤进
319px —— 问候语折成一字一行、数字和按钮直接溢出卡片。补齐 1180 / 900 两级降级后:

| 宽度 | 栏数 | 卡片高 | 溢出 |
| --- | --- | --- | --- |
| 1440 / 1280 | 3 | 264px | 无 |
| 1180 / 1024 | 2 | 366 / 347px | 无 |
| 900 / 640 / 390 | 1 | 320 / 185 / 211px | 无 |

### 2. 预测账单落在窗口外时,日历「没反应」的原因现在看得见了

反馈是「录入预测账单后,日历图没有任何变化」。**不是模型坏了**,是窗口外的账单在界面上
没有任何解释:默认只推演「未来 1 个月」(30 格),日期在此外的账单在列表里照常出现、
还计入「净影响」,日历却一格不动;列表里那条唯一的提示只是**整条透明度降到 0.55**。

```
账单列表:  远期账单 6月1日 −¥1千     ← 出现了
净影响:    −¥1.5千                  ← 计入了
日历:      30 格,一格没变           ← 用户看到的现象
```

- 窗口判定提到模型层:新增纯函数 `classifyForecastBillsByWindow()`,组件只负责显示。
  可见与否**以推演结果为准**,不只看日期 —— 周期性「每月」账单首次发生日可能更早,
  当期仍要出现在日历上(已用测试钉住)
- 列表里加可见的「不在区间」标记,文字不再整体降透明度
- 提示「其中 N 笔在当前区间之外」**并附一个「切到 12 个月」按钮**,点一下直接切过去
- 连 12 个月都覆盖不到的,单独说明「另有 N 笔日期离当前太远,任何区间都不显示」,
  免得白切好几次

### 3. 新增浏览器页面体检工具 `npm run audit:ui`

上面两个问题有个共同特征:**`tsc` / `eslint` / 1035 个单元测试全是绿的** ——
接口对不对有测试,「这条是不是被裁掉了」「这个数字读起来像不像时间」没人管。

`scripts/audit-ui-browser.mjs` 把 18 个路由 × 桌面(1440)/ 移动(390)跑一遍,量的是
**只有真渲染才存在**的几件事:整页横向溢出、越过视口右边界且不在横向滚动容器内的元素
(这类元素既不滚动也点不到)、没有可读名称的 button/a、每个路由新产生的 console error;
字号 < 11px 只报告不判失败(设计取舍,看趋势)。

- **不新增依赖**:优先用 `PLAYWRIGHT_MODULE` 指定的本地 playwright,否则依次找仓库内、
  DSH profile 里的那一份
- **已知误报写进 allowlist**:`/transactions` 移动端滑动条里的「删除 / 分享」位于视口外,
  是手势初始态(实际操作走「⋯」菜单),不算问题
- 不进 CI(需要先起后端与 dev server);用法写进 `docs/verified-invariants.md`

顺带把 `.playwright-mcp/` 加入忽略清单(浏览器工具会在仓库根写快照),并给
`check:dates` 补了 `assetLiabilitySimulation.ts` 的显式例外(预测账单的 date 已是纯
`YYYY-MM-DD`,写入时由 `normalizeDateOnly` 保证,不存在 UTC 截断问题)。
