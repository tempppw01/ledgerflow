## 订阅「已逾期」判定改成按本地日历日,不再随经度漂移

### 问题

`normalizeSubscriptionStatus` 用 `Math.ceil((到期时刻 - 现在) / 一天)` 比时间戳,而纯日期
到期日(`2026-11-20`)按 **UTC 零点** 解析。结果是「哪一刻算逾期」取决于时区 —— 同一份数据、
同一时刻,不同地区的用户看到不同状态:

| 时区 | 到期日当天最早出现「已逾期」的时刻 |
| --- | --- |
| Asia/Shanghai(UTC+8) | **次日** 08:00(到期日过了 8 小时才提示) |
| UTC | 次日 00:00 |
| America/New_York(UTC−5) | **当天** 19:00(到期日还没过完) |
| America/Los_Angeles(UTC−8) | **当天** 16:00(到期日还没过完) |

也就是说,**西部时区的用户会在到期日当天下午就被告知「已逾期」**,而东部时区的用户要到
第二天早上才看到提示。

### 修复

判定改为比较**本地日历日**:取出到期日所在的本地零点,与今天的本地零点比天数差。

- 纯日期(`2026-11-20`)表示「那一天」,用 `new Date(y, m-1, d)` 构造本地零点 ——
  直接用 `new Date('2026-11-20')` 会按 UTC 解析,在 UTC-8 落到本地 11-19,整整差一天
- 带时间的 ISO 表示一个瞬间,取它所在的本地日
- 天数差用 `Math.round`:夏令时切换那天两个本地零点相差 23 或 25 小时
- 语义变得可预期:**到期日当天算「即将到期」,次日起才算「已逾期」**,与用户看到的日期一致

顺带把这段逻辑从 `useFinanceStore.ts` 里抽成独立模块
`src/features/subscriptions/model/subscriptionStatus.ts`,可以单独测、也支持注入 `now`。

### 测试

新增 `subscriptionStatus.test.ts` **10 项**,覆盖:已暂停优先级、无到期日、非法日期、
到期日当天(00:05 与 23:55 都必须一致)、昨天、剩余 1–7 天边界与第 8 天、`expireDate`
优先于 `renewalDate`、带时间 ISO、跨月跨年、以及「一天 24 个整点都不跳变」。

**时区无关性**:同一套测试在 `Asia/Shanghai` / `UTC` / `America/New_York` /
`America/Los_Angeles` / `Pacific/Kiritimati`(UTC+14)下全部通过。

**反向验证**:把实现临时换回旧的时间戳比较,测试立刻 **8/10 失败**(三个时区都一样),
证明断言确实锁住了这个行为。
