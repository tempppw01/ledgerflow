## 重复导入账单时,「同一天」被日期格式判成「有变化」

这一版 1 个提交。

### 症状

同一天在库里有两种存法:

| 来源 | 存的格式 |
| --- | --- |
| 手动快记 | 纯日期 `2026-04-10`(`toLocalDateKey` 产出) |
| 助手导入 | ISO 瞬间 `2026-04-10T00:00:00.000Z`(`normalizeEntryDate` 产出) |

而账单导入的**变更检测**是直接比字符串:

```
existing.date !== incoming.date
```

于是「同一天、只是格式不同」被判成有变化。后果两条:

1. **每次重新导入同一笔账单都会发出一条 update** —— 报告里多出一批其实没变的「已更新」;
2. 那条 update 会把用户原来记的日期**格式一并改写**(纯日期 → ISO 瞬间)。

值得一处:同一个文件里的**去重键**本来就用 `resolveTransactionLocalDay` 归一到本地日,
只有变更检测这一处漏了。改法就是与它对齐。

### 验证

- 新增 3 条回归测试:同一天不同格式 → 算「没有变化」并进 `skipped`;真换一天 → 按身份键
  当成另一笔**新增**(身份键本身含日期);纯日期对纯日期 → 对照组
- **把比较改回字符串,第一条立刻失败**(期望 0 条更新,实际 1 条)
- 前端 **1128 项 / 150 文件**、服务端 **42 项**
- `tsc` 0、`eslint` 0、i18n 两闸门 0、`check:dates` 0、`check:money` 0、
  `check:shared-predicates` 0、`check:docs` 0

### 写测试时又踩到一次自己的前提错误

第二条用例我原本写「换一天应当**更新**」,结果失败 —— 因为身份键含日期,换一天就是另一笔,
应当走**新增**。不是代码的问题,是我对契约的理解错了;改正后它反而把身份键的规则钉住了。

这已经是这一段工作里第三次「测试没测到我以为的东西」(前两次:用「餐饮外卖」测新建失败、
按 created_at 排序查余额链)。共同点都是**先假设后验证**;写测试时先读一眼被测函数的契约,
能省掉这些往返。
