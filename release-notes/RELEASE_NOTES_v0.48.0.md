## 数据出入口与移动端:四处「看起来正常,其实不工作」的毛病

这一版 4 个提交(`v0.47.0..v0.48.0`),全部来自一次真机体验:用 MCP 浏览器把
**18 个路由 × 桌面(1440)/ 移动(390)** 两档宽度、浅色/深色、中文/英文都走了一遍,
并对着真实导出的文件跑了「导出 → 再导入」。

体检项:横向溢出、元素溢出视口、过小字号、没有可读名称的控件、控制台报错、
以及 DOM 层面的嵌套 `button`/`a`。下面四处问题都是它抓出来的 —— 共同点是
**界面照样给"正常"的反馈,用户完全看不出来**。

### 1. 本 App 自己导出的交易 CSV,自己导不回来(整份文件 0 条)

「导出交易明细 → 再导入」这条闭环从来没通过。导出走英文列名(`date` / `amount` / `type`),
导入只认中文表头,于是整份文件解析出 **0 条**,界面还提示"导入成功"。

逐个定位到**三处独立根因**,缺一处都修不好:

| # | 根因 | 后果 |
| --- | --- | --- |
| 1 | `AMOUNT_KEYS` 里没有 `amount` | 表头判定要求「必须有金额列」→ 判否 → 连表头都没找到,整份文件归零 |
| 2 | `pickByKeys` 用子串匹配 | 找「成功退款」时先撞上 `amount` 列,把 **支出金额当成退款额**,¥58.00 被算成"全额退款"→ 整行丢弃 |
| 3 | `parseType` 读错了列 | 英文类型判定读的是「收/支」列(空的),判断永远不生效 → 支出一律记成收入 |

顺带修掉:ISO 时间戳里的毫秒点号被日期归一化替换成 `-`,让每一行都"有日期列但解析失败";
清单里重复写了两遍的「金额(元)」(第二项本该是全角括号)。

新增回归测试 `src/shared/lib/csv.roundtrip.test.ts`,并在浏览器里用**两端的真实代码**
跑通了闭环:3 条(支出 / 收入 / 还款)全部还原,金额、方向、日期、含引号的备注逐项一致。

### 2. 移动端整页被撑到 545px,右侧内容直接看不见

`/balance-changes` 在 390px 视口下:页面容器是单列 grid,而 grid 项默认
`min-width: auto` —— 列宽被内容的**最小宽度**顶到 **544.98px**;`.workspace` 是
`overflow-x: hidden`,超出的部分既不产生滚动条也点不到,被直接裁掉 186px:
汇总卡片的「增加 / 13 笔」、表单的「全部账户」全都看不到,界面上没有任何提示。

根治放在通用层:`.vi-page`(18 个页面共用)加 `grid-template-columns: minmax(0, 1fr)`。
只改这一个类,**不动任何单页样式**。

### 3. 投资「今天的市场」把综合分读成了时间

原文案把有符号的综合分(范围 -100~100)拼进一整句话:

```
先用本地信号 · 配置 AI 后每 15 分钟更新 · 综合 -23 · 风险 96
```

「-23」紧跟在「更新」后面,读起来像**"更新晚了 23 分钟"**;而这两个值
**全项目只在这一处展示**。

改成各自带标签的独立小块,并按松紧分档配色:`综合分 -23`(中性)、`风险 96`(高风险红)。
说明文字只讲数据来源与刷新频率。顺带清掉残留在状态串尾巴上的「· 综合」残句。

### 4. 概览页问候语少一个空格

中文的 `dashboard.ui.greetingFormat` 是 `{{greeting}},{{welcomeTitle}}`,拼出来是
**「夜深了,注意休息,LedgerFlow」** —— 中文逗号后紧贴拉丁字母;而英文同一份模板
是 `{{greeting}}, {{welcomeTitle}}`,本来就带空格。说明空格一直是有意的,
只是中文那份漏了。已补齐。

### 体检结论(确认不是问题的部分)

- 18 个路由在两种宽度下**均无控制台报错**(含 React 报错)、无嵌套 `button`/`a`
- 交易页移动端那两个「删除 / 分享」按钮位于视口外,是滑动手势的初始态
  (实际操作走卡片右上角「⋯」菜单),**不是缺陷**
- 主题切换器需要悬停展开(约 0.2s),浅色/深色/跟随系统三态均正常
- 英文模式下剩余的中文是**用户自己的数据**(分类名、账户名、订阅名)与中文新闻源,属预期
