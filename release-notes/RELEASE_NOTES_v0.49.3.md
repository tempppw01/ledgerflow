## 两个「用户看得见,但没人报告」的缺口:断网时的英文串、保存后的沉默

这一版 2 个提交,都是把**核心流程真的走一遍**才发现的 —— 一个是错误态,一个是交互闭环。
两者的共同点:功能本身没错,但**界面给了错误或空洞的反馈**。

### 1. 断网时把浏览器内部的英文串显示给了用户

把后端请求全部阻断后,登录页显示的是:

```
LEDGERFLOW ACCOUNT | 登录 LedgerFlow | ... | Failed to fetch | 登录 | ...
```

`Failed to fetch` 是浏览器内部文案,用户只会以为应用坏了。

根因是**两类失败被一视同仁**:`AuthGate` 两处都是
`reason instanceof Error ? reason.message : tf(...)` —— 只要拿到 `Error` 就原样上屏。
但账号接口的失败分两类:

| 失败来源 | message | 该不该给用户看 |
| --- | --- | --- |
| 服务端业务失败 | `邮箱或密码不正确。` | ✅ 必须保留,否则用户不知道错在哪 |
| HTTP 非 2xx | `HTTP 503` | ❌ 技术串 |
| 网络不可达 | `Failed to fetch`(浏览器内部) | ❌ 英文技术串 |

所以不能简单改成"永远用兜底文案"(那会丢掉第一类),只能按 message 的形状区分。

**改法**:新增 `shared/lib/requestErrorText.ts`,把判断收敛成单一来源 ——
`isBrowserNetworkFailure()` 认得三大浏览器的文案(Chrome `Failed to fetch`、
Safari `Load failed`、Firefox `NetworkError …`)。这个判断原来散着三份,
而登录页正因为没做它才漏出去。

**同类问题不止登录页**:顺着查出 `InvestmentsPage` 有 **5 处**同样写法
(历史行情、快讯、板块行情、定投模拟、个股搜索),展示在空状态与 toast 上,已全部改掉。
顺带收益:这些中文文案原来写死在代码里,现在走 i18n,英文界面下能正确翻译。

### 2. 编辑保存成功后,没有任何反馈

把「记一笔 → 改 → 删」完整走一遍。改完金额点保存,连续采样 4 秒、10 次:

```
anyFeedback = false
  url: /transactions(已跳回列表)
  toast: false
  role=status/alert: []
```

`TransactionEditPage` 的保存逻辑是:

```ts
try {
  updateTransaction(id, payload);
} catch (error) {
  setFormError(...);   // 失败:有提示
  return;
}
navigate('/transactions');   // 成功:直接跳走,什么都没有
```

**失败路径有提示,成功路径反而没有。** 用户点了保存、页面跳回列表,
只能自己一行行翻找那笔改没改 —— 而列表页其它操作(快速记账、导入)都有成功 toast。

**改法**:保存时通过路由 state 把提示带到列表页,新增/更新分开措辞;
列表页消费后立刻清掉 state,否则浏览器后退/前进回到该记录时 toast 会重复弹。

### 顺带确认**没问题**的两处

- 列表删除有二次确认(「确认移入回收站」),文案说清了「之后仍可在回收站恢复」
- 详情 → 编辑是跳转独立页,原值(金额/备注/分类/账户/状态)全部正确回填
