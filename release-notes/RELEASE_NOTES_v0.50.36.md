## 「预算」型交易不再被算作支出

三件待决事项的最后一件。这一版改的是**一个数字的口径**,依据是代码自己的一致行为,不是偏好。

### 之前的问题

`transactionMetrics.isExpenseLike`(`summarizeTransactions` 与财务分析页用它)**含** `budget`,
而首页的 `isActualExpenseType` **不含** —— 于是首页一屏之内,「本月结余」和「钱都去哪了」
给出互相矛盾的两个数字。谁对?代码里没有任何一句话说明「预算」型交易到底意味着什么。

### 定案的依据:五比一

我把全项目对「预算」型的处理逐个查了一遍:

| 面 | 预算型算支出吗 |
| --- | --- |
| 首页「本月结余」(`isActualExpenseType`) | 不算 |
| 智能预算 · 已花费(`budgetDetail.ts:87`) | 不算 |
| 智能预算 · 洞察(`budgetInsights.ts:73`) | 不算 |
| 分类预算明细 | 不算 |
| 助手发给模型的账本合计 | 不算 |
| `isExpenseLike`(经共享汇总 + 财务分析页) | **算** ← 唯一的例外 |

**五处不计入、一处计入** → 把那一处对齐到其余五处。

### 改了什么

- `isExpenseLike` 去掉 `budget` → **支出 + 还款**;
- 首页的 `isActualExpenseType` 保持原样(它本来就对),补注释说明两者现在一致;
- `shared/lib/expenseScope.contract.test.ts` 从「钉住两者的差异」改成「钉住统一后的契约」
  (两边判定必须一致、预算型两边都不算);
- 文档:交接说明的 `### 5` 与不变量清单里的待决事项都改成已定案,并把上面那张五比一的表记进去;
- `check:shared-predicates` 里那条豁免的理由同步改写(它原来写的是「两个有意不同的概念」)。

### **这不等于「预算型不影响余额」**

预算型交易照样写 `transaction-budget` 余额变动 —— 钱确实从账户里划走了。变的只是**各处的
「支出」统计不再把它算作花掉**。这条区别已写进代码注释和文档,免得被下一个读代码的人误解。

### 验证

- 契约测试 4 条全过;**证伪**:把 `isExpenseLike` 改回含 `budget` → 4 条里 3 条失败,
  还原后全过;
- **全量前端 1167 项一次通过** —— 说明没有任何其它测试依赖「预算算支出」这个旧行为,
  改动范围确实很窄;
- 服务端 48 项、九道闸门、演示账本基线、账目口径体检全部 0。

### 影响面

演示账本里**没有**任何 `budget` 型交易(283 支出 / 12 收入 / 3 还款),所以这个改动在演示数据上
看不出差别。它只影响真正创建过「预算」型交易的用户:那些数字会**变小,并且各处一致**。

如果你想反过来(让首页也把预算占用算进支出),说一声 —— 改一行、契约测试会告诉我还有哪里要跟着改。
